# assetsgen —— 视觉素材生成

这个阶段负责**产出素材文件**：位图（调生图模型）与 SVG（素材库 / 模型）。
它消费 `design-sketch` 阶段的版式规格（`design-sketch.json`），产出的素材由
final 组装（目前还在 `scripts/step-layout.ts` 的 final 段）回填进成品图。

**与 design-sketch 的衔接点只有一个字符串**：节点的 `asset: "hero.png"` =
订单的 `file: "hero.png"`——直接拿文件名当引用，不做 id 映射。

---

## 文件

| 文件 | 职责 |
|---|---|
| `asset-order.ts` | **契约**：生图订单（`AssetRequest`：file / size / prompt / references / useSketchRef）|
| `image.ts` | **生成**：读订单 → 商品抠图（按需）→ 草图按图位裁切 → 调 seedream（审核重试）|
| `cutout.ts` | **商品照预处理**：实测主体边界 / 阈值抠白底 / 裁刻字区 / 压参考图 |
| `README.md` | 本文件 |

**入口**：`scripts/step-layout.ts -- <规格.json> gen`（CLI 壳，实现在本目录）。

## 四条硬约束（实测，内核已封装——不要在各处重复处理）

| 约束 | 数值 / 规则 |
|---|---|
| 参考图 | **最多 2 张**同时传 |
| 输出尺寸 | **下限 3,686,400 像素**（横版 `2560x1440` / 竖版 `1440x2560` 正好卡下限）|
| 提示词 | **避免品牌 / 水印类词汇**（实测德语 Logos/Marken/Wasserzeichen 触发审核——"禁止品牌标识"这条指令本身就会触发；改写成「Enthält keine Schriftzeichen」类描述）|
| 内容审核 | **概率性**（同一输入时过时不过）→ 内核自动重试 3 次 |

## 草图作为构图参考——**按图位裁切，不传整张**

`useSketchRef`（默认 true）会把版式草图作为 **compose 参考**传给生图模型。
但传的是**按素材所属 image 节点的 `rect` 裁出来的区域**，不是整张：

> 实测：整张草图传进去，模型会把草图下半的**文字占位条**也当设计画进素材
> （fitness-app 那次：晨跑剪影很好，下半把灰条全画了）。
> 素材是**填进某个图位**的，参考图就该只给**那个图位**的构图。

图位是全幅（如电影海报的 hero）时，裁出来就是整张，行为不变。

**商品抠图同样是按需的**：只有订单引用 `@product` 时才跑抠图流程；
纯场景版式（如健身 App 的晨跑剪影）不需要商品照，整段跳过。

**参考图分辨率不能压**：曾经默认 768px，商品上的雕刻小字读不清，
生成时模型只能**编造**（畸形 / 截断）。原尺寸传入后逐字全对——
**我们把证据弄糊了再让它抄**。参考图是模型唯一的身份来源。

## 提示词语言

**默认 en**（`--prompt-lang` 可指定）——提示词的读者是**生图模型**，不是终端消费者：
seedream 是中英双语原生模型（官方文档：所有模型支持中英文，德语等是 5.0
额外支持的语言），用市场语言写 prompt 是把二等公民语言喂给模型。
画面里需要什么语言的文字，由 brief 决定并最终由 HTML 渲染——
**生图模型不画字，提示词语言与目标市场没有必然关系**。
语言随订单落盘（`promptLang` 字段）：gen 阶段拼参考图角色说明时按它选语言，订单自包含。

## 提示词写法——先分清模型类型

生图模型分两种"方言"，**写法互不通用**：

| | **指令型**（seedream / Flux / GPT-image 类）| **标签权重型**（Midjourney / SD1.5 / SDXL）|
|---|---|---|
| 句式 | 完整自然语言句子 | 逗号分隔关键词堆 |
| 权重 | **无效**——改用「以…为主」的表述 | `(red dress:1.4)` / `marble::2` |
| 质量词堆砌（masterpiece / 8k…）| **有害无益** | 有一定效果 |
| 负向词 | 不需要 | 常规手段 |

**当前接入的都是指令型。** 写 prompt 按**七要素**组织：

1. **主体**——是什么（可带需要模型注意的细节）
2. **动作与状态**
3. **场景**——发生在哪里
4. **风格与媒介**——什么质感的照片（商业产品摄影 / Kodak Portra 400 胶片…）
5. **光线与色调**——光源方向与色温（左侧柔光箱 / 暖钨丝灯＋冷蓝阴影…）
6. **构图·镜头**——怎么拍（45° 俯视 / 85mm f/1.4 / 浅景深 / 留白…）
7. **技术参数**——**不写进 prompt**：`size` 是订单的独立字段

`image.ts` 会对权重语法和质量词堆砌给 **warn**（不拦流程）；
审核禁词则直接 **throw**（拦在调 API 之前，省钱）。

## 电商生图模板——商品图的收敛结构

**先看图的用途。** 电商商品图把泛用七要素收敛为**六段**：

| 段 | 内容 |
|---|---|
| **产品事实** | 材质 ＋ 颜色 ＋ 造型（模型只能靠这段知道"它是什么"）|
| **镜头角度** | 正拍 / 45° 俯视 / 特写… |
| **光线** | 方向与色温 |
| **背景** | 场景或纯色 |
| **约束** | 比例、无文字、无 logo |
| **保真声明** | **keep the shape, lid, label and color exactly the same, do not add extra text or graphics** |

**保真声明是商品图与艺术图的唯一实质区别。** 漏掉它，模型会擅自改 logo、
增删部件——直接对应平台「与实物不符」违规、退货与广告拒审。
（引用 `@product` 的订单若缺保真声明，`image.ts` 会 warn。）

### 整套图的一致性

同一产品的多张图要像「同一次拍摄」：**只换场景或角度，
锁定光照 / 色温 / 背景基调**。这条将作为约束写进订单生成。

### 多图输入：每张参考图指派明确角色

不能只堆图。每张参考图要说清它负责什么——**轮廓**（subject）、
**材质**（detail）、**接口 / 局部**（detail）——对应契约的 `ReferenceRole`
（`subject` / `compose` / `style` / `detail`）。

  拒绝 `<script>` / `on*=` / `javascript:`）
