# assetsgen —— 视觉素材生成

这个阶段负责**产出素材文件**：位图（调生图模型）与 SVG（素材库 / 模型）。
它消费的是**文档模型本身**：`DesignDocument`（落盘 `<工作目录>/designs/<版式名>/doc.json`）——
`order.ts` / `image.ts` 都收 `spec: DesignDocument`，按其中 `image` 元素的 `asset` 找图位
（`order.ts` 的 `imageNodes()`、`image.ts` 的 `imageNodeOf()`）。
⚠️ **旧口径已作废**：`design-sketch` 阶段与 `design-sketch.json` 契约**整层已删**；
产出素材也不再由 `compose/assemble.ts` 的 `assembleFinal()` 回填，而是交给
`render/vocabulary/emit.ts` 的 `emitDocument(doc, { assets })` —— 渲染那一步现场消费。

**与文档的衔接点只有一个字符串**：元素的 `asset: "hero.png"` =
订单的 `file: "hero.png"`——直接拿文件名当引用，不做 id 映射。

| 约束 | 数值 / 规则 |
|---|---|
| 参考图 | **最多 2 张**同时传 |

## 草图**默认不传**（`useSketchRef` 默认 false）

`useSketchRef` 曾经默认 `true`，把版式草图作为 **compose 参考**传给生图模型。
**2026-10-11 改为默认 `false`**，原因：

> 草图不只是"区域框"——它还画着**图层名文字**（`label()`）、**虚线框**（`sbox`）、
> **12 等分网格**（`sgrid`）。这些辅助标记会被生图模型**当设计画进素材**。
> 实测（gogokids-swim-vest 场景图）：图位里的中文图层名
> 「场景图：湖畔浅水（家长在旁扶着，明亮夏日）」被整条画进了场景照片里。

**"按 rect 裁切"救不了**——那些标记就画在图位**内部**，裁完照旧在
（这是旧版"裁切即可解决"假设的失效点）。

场景图 / 环境图本来就该填满图位，构图由 **brief 的文字意图**描述即可。
确需草图构图参考的订单，**显式**写 `useSketchRef: true`。

**商品抠图同样是按需的**：只有订单引用 `@product` 时才跑抠图流程；
纯场景版式不需要商品照，整段跳过。

**参考图分辨率不能压**：曾经默认 768px，商品上的雕刻小字读不清，
生成时模型只能**编造**（畸形 / 截断）。原尺寸传入后逐字全对——
**我们把证据弄糊了再让它抄**。参考图是模型唯一的身份来源。

## 提示词语言

**默认 en**（`--prompt-lang` 可指定）——提示词的读者是**生图模型**，不是终端消费者：
seedream 是中英双语原生模型（官方文档：所有模型支持中英文，德语等是 5.0
额外支持的语言），用市场语言写 prompt 是把二等公民语言喂给模型。
画面里需要什么语言的文字，由 brief 决定并最终由 HTML 渲染——
**生图模型不画字，提示词语言与目标市场没有必然关系**。
语言随订单落盘（`promptLang` 字段）：gen 阶段拼参考图角色说明时按它选语言，订单自包含。

## 提示词写法——先分清模型类型

生图模型分两种"方言"，**写法互不通用**：

| | **指令型**（seedream / Flux / GPT-image 类）| **标签权重型**（Midjourney / SD1.5 / SDXL）|
|---|---|---|
| 句式 | 完整自然语言句子 | 逗号分隔关键词堆 |
| 权重 | **无效**——改用「以…为主」的表述 | `(red dress:1.4)` / `marble::2` |
| 质量词堆砌（masterpiece / 8k…）| **有害无益** | 有一定效果 |
| 负向词 | 不需要 | 常规手段 |

**当前接入的都是指令型。** 写 prompt 按**七要素**组织：

1. **主体**——是什么（可带需要模型注意的细节）
2. **动作与状态**
3. **场景**——发生在哪里
4. **风格与媒介**——什么质感的照片（商业产品摄影 / Kodak Portra 400 胶片…）
5. **光线与色调**——光源方向与色温（左侧柔光箱 / 暖钨丝灯＋冷蓝阴影…）
6. **构图·镜头**——怎么拍（45° 俯视 / 85mm f/1.4 / 浅景深 / 留白…）
7. **技术参数**——**不写进 prompt**：`size` 是订单的独立字段

`image.ts` 会对权重语法和质量词堆砌给 **warn**（不拦流程）；
审核禁词则直接 **throw**（拦在调 API 之前，省钱）。

## 引用 `@product` 时的保真声明（`image.ts` 会 warn）

订单**引用 `@product`**（把主体实物照当参考图）时，提示词里应有**保真声明**——
否则模型会擅自改 logo、增删部件，成品与实物不符。

> 典型句式：`keep the shape, lid, label and color exactly the same, do not add extra text or graphics`

（`image.ts` 的 `warnFidelity` 在引用 `@product` 却无保真表述时 warn，不拦流程。）

**保真声明要写成中性句式**，不要绑定某个行业——具体行业的保真措辞由**创意方案（brief）**指定，
`order-system.md` 只提供机制。

### 「主体在场景中」——主体与环境画在**同一张图**里

图位要展示「主体摆放在某个真实环境里」时，**不要让生图模型只画空场景**——
必须用 `@product` 引用实物照，提示词里把**主体 + 具体场景**一起写全，
由生图模型直接产出「主体在场景中」的完整照片。

⚠️ **禁止「空场景 + 图层事后叠加」**：这条现在**基本没有例外**——
单独的「纯背景素材」（`bg-*` 类）**已不建议生成**（见 `order-system.md`
「禁止单独的『纯背景素材』」，两条实测理由：必然叠出矩形边界 + 否定词无效）。
主体要环境就让**主体素材自带环境**；只要底色就用 **HTML/CSS**。

实测事故：订单被写成 `empty desk … reserved for a product photo
to be composited on top later` → 生成一张**空桌子** → 主体以**白底矩形硬贴**上去，穿帮。
判据：**这个图位最终要不要显示主体？要 → 就在场景里把主体画出来。**

### 整套图的一致性

同一批交付的多张图要像「同一次拍摄」：**只换场景或角度，
锁定光照 / 色温 / 背景基调**。（例外：图位本身要**对比不同场景**时，
场景内容就该明显不同——锁定的只是光照 / 色温基调。）

### 多图输入：每张参考图指派明确角色

不能只堆图。每张参考图要说清它负责什么——**轮廓**（subject）、
**材质**（detail）、**接口 / 局部**（detail）——对应契约的 `ReferenceRole`
（`subject` / `compose` / `style` / `detail`）。
