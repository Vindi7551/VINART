# assetsgen —— 视觉素材生成

这个阶段负责**产出素材文件**：位图（调生图模型）与 SVG（素材库 / 模型）。
订单由**主 AI 在 `generate_assets` 参数里直接写**（`images[]`）——本目录不再有“订单生成”模块，
生成（`image.ts`）**只认订单**，不读文档。
⚠️ **旧口径已作废**：`design-sketch` 阶段与 `design-sketch.json` 契约**整层已删**；
产出素材也不再由 `compose/assemble.ts` 的 `assembleFinal()` 回填，而是交给
`render/vocabulary/emit.ts` 的 `emitDocument(doc, { assets })` —— 渲染那一步现场消费。

**与文档的衔接点只有一个字符串**：元素的 `asset: "hero.png"` =
订单的 `file: "hero.png"`——直接拿文件名当引用，不做 id 映射。

## 文件

| 文件 | 职责 |
|---|---|
| `asset-order.ts` | **契约**：生图订单（`AssetRequest`：file / size / prompt / references）|
| `image.ts` | **生成**：读订单 → 调 seedream（审核重试）|
| `README.md` | 本文件 |

**入口**：本目录的 `generateAssets()`。
聊天链的 `generate_assets` 工具已在 `designharness/tools/generate-assets.ts` 重新长回来：
`images` 走本目录，`icons` 是主 AI 写的线框 SVG（工具只做安全检查 + 落盘）。
它不是旧契约的 `generate_assets`，产物仍是 `doc.json` 引用的素材文件。

## 工具契约（2026-10-21 补齐）

- **入参校验**：`file` 必须是 `.png` 纯文件名、`prompt` 非空、`size` 格式与像素下限、
  `references` 是数组且 ≤14 张——**有问题一张都不生成**，一次列全部问题；
- **同名默认跳过**；要重画同一张传 `overwrite: true`；
- **下载后校验 PNG 魔数**：不是 PNG 就判失败，不写“假 .png”；
- **逐张进度**：每张完成发 `asset-progress` 事件（聊天里显示一行 log）；
- **订单留底**：合并写入 `<layout>/assets.json`（按 file 去重），失败也写；
- **取消**：`generateAssets` / gateway 已接 `AbortSignal`（进行中的请求可中断），
  但聊天界面**还没有停止按钮**——signal 目前没有入口。

## 四条硬约束（实测，内核已封装——不要在各处重复处理）

| 约束 | 数值 / 规则 |
|---|---|
| 参考图 | **不设硬上限**（方舟 ≤14 张）；超过 2 张只提示「主次容易乱」|
| 输出尺寸 | **下限 3,686,400 像素**（横版 `2560x1440` / 竖版 `1440x2560` 正好卡下限）|
| 提示词 | **避免品牌 / 水印类词汇**（实测德语 Logos/Marken/Wasserzeichen 触发审核——"禁止品牌标识"这条指令本身就会触发；改写成「Enthält keine Schriftzeichen」类描述）|
| 内容审核 | **概率性**（同一输入时过时不过）→ 内核自动重试 3 次 |

## 草图参考已删除（2026-10-20）

`@sketch` / `useSketchRef` 整条能力已移除：草图（`sketch.png`）**早就没有生产者**，
带草图的订单会在读文件时直接 ENOENT；而且草图上画着**图层名文字**、**虚线框**、
**12 等分网格**，实测会被生图模型**当设计画进素材**（按 rect 裁切也救不了）。

构图交给 **brief 的文字意图**；要参考真实图片，就用 `references` 里的文件名。

**商品照就是一张普通参考图**（2026-10-20）：不再有 `productPath` / `@product` /
抠图预处理——用户贴的商品照落在 `<workDir>/uploads/`，直接写进 `references`
（如 `"uploads/chat-xxxx.png"`）即可。参考图按 **版式目录 → 工作目录** 的顺序找文件。

**参考图原图直传，不压缩**（2026-10-21）：曾经默认 768px，商品上的雕刻小字读不清，
生成时模型只能**编造**（畸形 / 截断）；后来改成压到 2048/1024，仍会丢 alpha、糊小字。
现在直接读原文件字节（mime 按文件头判断），PNG 的 alpha 也保留。

⚠️ 代价是请求体变大：参考图是 base64 data URL。**实测请求体上限 128 MiB**
（134MB 的 data URL 通过、135MB 返回 413 `EntryTooBig`）；代码在合计 >120MB 时提示。

## 提示词语言

**默认 en**（`--prompt-lang` 可指定）——提示词的读者是**生图模型**，不是终端消费者：
seedream 是中英双语原生模型（官方文档：所有模型支持中英文，德语等是 5.0
额外支持的语言），用市场语言写 prompt 是把二等公民语言喂给模型。
画面里需要什么语言的文字，由 brief 决定并最终由 HTML 渲染——
**生图模型不画字，提示词语言与目标市场没有必然关系**。
语言随订单落盘（`promptLang`）：提示词里没有中文时，gen 阶段按它拼参考图说明
（**含中文就自动用中文**——走 `generate_assets` 工具时订单里原本没有这个字段）。

---

## 提示词写法——先分清模型类型

生图模型分两种"方言"，**写法互不通用**：

| | **指令型**（seedream / Flux / GPT-image 类）| **标签权重型**（Midjourney / SD1.5 / SDXL）|
|---|---|---|
| 句式 | 完整自然语言句子 | 逗号分隔关键词堆 |
| 权重 | **无效**——改用「以…为主」的表述 | `(red dress:1.4)` / `marble::2` |
| 质量词堆砌（masterpiece / 8k…）| **有害无益** | 有一定效果 |
| 负向词 | 不需要 | 常规手段 |

**当前接入的都是指令型。** 写 prompt 按**七要素**组织：

1. **主体**——是什么（可带需要模型注意的细节）
2. **动作与状态**
3. **场景**——发生在哪里
4. **风格与媒介**——什么质感的照片（商业产品摄影 / Kodak Portra 400 胶片…）
5. **光线与色调**——光源方向与色温（左侧柔光箱 / 暖钨丝灯＋冷蓝阴影…）
6. **构图·镜头**——怎么拍（45° 俯视 / 85mm f/1.4 / 浅景深 / 留白…）
7. **技术参数**——**不写进 prompt**：`size` 是订单的独立字段

`image.ts` 会对权重语法和质量词堆砌给 **warn**（不拦流程）；
审核禁词则直接 **throw**（拦在调 API 之前，省钱）。

## 引用商品照时的保真声明（`image.ts` 会 warn）

订单**用了参考图**时，提示词里应有**保真声明**——
否则模型会擅自改 logo、增删部件，成品与实物不符。

> 典型句式：`keep the shape, lid, label and color exactly the same, do not add extra text or graphics`

（`image.ts` 的 `warnFidelity` 在有参考图却无保真表述时 warn，不拦流程。）

**保真声明要写成中性句式**，不要绑定某个行业——具体行业的保真措辞由**创意方案（brief）**指定。

### 「主体在场景中」——主体与环境画在**同一张图**里

图位要展示「主体摆放在某个真实环境里」时，**不要让生图模型只画空场景**——
必须把商品照写进 `references`，提示词里把**主体 + 具体场景**一起写全，
由生图模型直接产出「主体在场景中」的完整照片。

⚠️ **禁止「空场景 + 图层事后叠加」**：这条现在**基本没有例外**——
单独的「纯背景素材」（`bg-*` 类）**已不建议生成**（两条实测理由：必然叠出矩形边界 + 否定词无效）。
主体要环境就让**主体素材自带环境**；只要底色就用 **HTML/CSS**。

实测事故：订单被写成 `empty desk … reserved for a product photo
to be composited on top later` → 生成一张**空桌子** → 主体以**白底矩形硬贴**上去，穿帮。
判据：**这个图位最终要不要显示主体？要 → 就在场景里把主体画出来。**

### 整套图的一致性

同一批交付的多张图要像「同一次拍摄」：**只换场景或角度，
锁定光照 / 色温 / 背景基调**。（例外：图位本身要**对比不同场景**时，
场景内容就该明显不同——锁定的只是光照 / 色温基调。）

### 不做白底棚拍 / 不下「纯背景」订单

（从已删除的 `order-system.md` 迁移；这是生图质量的硬规则）

除平台强制纯白的主图外，**默认不要写白底 / 灰底 / 摄影棚布光**——成品会像电商图集：

- **环境要具体**（木质门廊 + 散落落叶 / 门口暖光地毯），不要 `unstyled plain background` / `studio seamless backdrop`；
- **光线要「有来源」**（窗外斜射的午后光 / 暖色室内灯），不要「均匀柔光箱 / studio lighting」；
- 需要「干净背景」时用**浅景深的真实环境**（虚化的店内 / 木墙），不要纯色渐变。

**不要下只画背景的订单**（`bg-*` / `leaf-bg` / prompt 写「只有纹理 / 满幅底纹」）：

1. 它必然要和主体素材叠——就是「背景 + 主体」两段式，成品会露**矩形边界**
   （实测 prompt 写 `no hard rectangular seams` 也拦不住）；
2. **否定词对当前模型基本无效**——背景越空，模型越要往里加东西
   （实测在“空背景”上画了整副中文海报）。

要环境 → 让**主体素材自带**；要底色 → 交给 **HTML/CSS**（`shape.fill`）。

### 多图输入：`[图片N]` 在提示词里点名

不能只堆图——每张参考图负责什么，要在**提示词正文**里说清：

> 「[图片1] 是商品照，外观必须一致，然后放在场景里重拍；[图片2] 只取纹理。」

`references` 里只有文件名，**没有 role 字段**（2026-10-20 删除）。提示词里的
`[图片1]` / `[图片 1]` / `[Image 1]` 会在发送前编译成「第 1 张（文件名）」
（英文按 `Reference 1 (文件名)`）——生图模型不认识方括号记号，这一步省不掉。

⚠️ **编号按原始顺序算，被丢掉的参考图会让后面的编号前移**：编译时用
“原始编号 → 最终编号”换算；指不到的编号原样保留并记 warning。

### 为什么不用 `@`

`@` 在聊天里已经用来指画布元素（`@主标题`），在生图提示词里再指参考图，
同一个符号两套含义，主 AI 会混。方括号是第三套记法，两边都不撞。

## SVG 素材（规划中）

素材库已在 `designassets/elements/icons/*.svg`（10 个）。
契约里暂缓的 **icon 能力**回来时，实现落在这个目录：
- **素材库按名取**（`"icon": "ahorn"`）—— 会重复用的图形

  拒绝 `<script>` / `on*=` / `javascript:`）
- 三级阶梯：**结构化字段 → 素材库 → 内联**，优先级从上到下
