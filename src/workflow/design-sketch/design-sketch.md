# DesignSketch 契约 —— 供模型阅读的版本

你的任务：**把一份「创意方案」翻译成 `design-sketch.json`。**

这份文件不是给人读的说明，而是**机器可渲染的排版规格**——渲染器会拿它画出草图。
所以每个字段都要精确、可执行。

---

## 一、一个设计只有三样东西

```
   图  ·  文字  ·  形状
```

任何平面设计 = **内容 × 排布**。内容只有两类（图 / 文字）；
排布靠**位置与尺寸**；而画面里那些"块"——框、底板、分区——是第三类。

| type | 是什么 | 必填字段 |
|---|---|---|
| `image` | **一张照片 / 场景 / 商品图** | `asset` |
| `text` | **要出现在画面上的文字** | `text` |
| `shape` | **一个形状块**：当框用、当底板用、当分区用 | `shape` |

三类**都必须有** `id` 和 `rect`。

**主次靠尺寸自然表达**——数据里不用写"这是主图"。
主图自然就大、就居中；次级图自然就小、就在边上。

---

## 二、`rect`：唯一的位置与尺寸写法

位置与尺寸**只有一种写法**，一律 **0–1 画布比例**，不是像素：

```jsonc
"rect": { "x": 0.55, "y": 0.08, "w": 0.38, "h": 0.84 }
```

| 想表达 | 就写 |
|---|---|
| 铺满整个画布 | `{ "x": 0, "y": 0, "w": 1, "h": 1 }` |
| 左上角起，占宽 38%、高 84% | `{ "x": 0.55, "y": 0.08, "w": 0.38, "h": 0.84 }` |
| 水平居中、位于上方 15% | `{ "x": 0.2, "y": 0.15, "w": 0.6, "h": 0.08 }` |

**绝不要写像素**（`"x": 70` 是错的），也**不要把 x/y/w/h 写在节点顶层**——必须在 `rect` 里。

## 三、`transform`：旋转与斜切（三类节点都能用）

**整块可省 = 不旋转也不斜切。** 里面所有字段也都是可省的：

```jsonc
"transform": {
  "rotate": -8,                      // 旋转角度：度，**顺时针为正**。省略 = 不转
  "skewX": 0.15,                     // 水平斜切：顶边相对底边向右错开 15%。省略 = 不斜切
  "origin": { "x": 0.5, "y": 1 }     // 支点：相对 rect 自身，0–1。省略 = 中心
}
```

⚠️ **`transform` 里至少要有一个真正的变换**（`rotate` 或 `skewX`）。
`origin` 是它们的**支点**，单独出现没有意义。

**`origin` 常用值**：

| 想绕哪转 | `origin` |
|---|---|
| 中心（最常用，可省略） | `{ "x": 0.5, "y": 0.5 }` |
| 左上角 | `{ "x": 0, "y": 0 }` |
| 左下角（像立在桌上的牌子那样转） | `{ "x": 0, "y": 1 }` |
| 上边中点 | `{ "x": 0.5, "y": 0 }` |

**什么时候用旋转**：

| 用途 | 角度 | 典型场景 |
|---|---|---|
| 微倾——照片散落、卡片轻微歪 | `-4 ~ 4` | 一叠照片、随手放的东西 |
| 斜排——一组标签整体倾斜 | `-30 ~ -10` / `10 ~ 30` | 斜着的标签组 |
| 直角——竖排大字 | `±90` | 画面侧边的标题 |

**一条纪律**：**同一组的角度差要小且有规律**——一叠照片都在 ±8 内看着舒服；
从 `-30` 跳到 `+25` 就是纯乱。

⚠️ **旋转和斜切都不改变 `rect`**：`rect` 永远是变换**之前**的矩形。
所以对齐、间距都按 `rect` 算，你**不用**去算变换后的位置。
但注意：**变换过的框会超出原来的范围**（一个 `0.30 × 0.05` 的横条转 45°，
视觉上要占约 `0.25 × 0.25`），所以**留足余量**，别贴着画布边缘转。

## 四、三类节点的全部字段

### `image` —— 图

```jsonc
{ "id": "hero", "name": "主图", "type": "image",
  "asset": "hero.png",
  "rect": { "x": 0.05, "y": 0.15, "w": 0.45, "h": 0.6 },
  "fit": "contain" }
```

| 字段 | 说明 |
|---|---|
| `asset` | 素材**文件名**（如 `hero.png`）。它由素材订单生产，你只写名字 |
| `fit?` | `cover`（默认，铺满、超出裁掉——场景照用）/ `contain`（完整放进——**商品图用**，不能裁到主体）|

### `text` —— 文字

```jsonc
{ "id": "title", "name": "主标题", "type": "text",
  "text": "NOIR 07",
  "rect": { "x": 0.6, "y": 0.15, "w": 0.28, "h": 0.08 },
  "fontScale": 0.05, "weight": 900, "align": "center" }
```

| 字段 | 说明 |
|---|---|
| `text` | 一行用字符串；多行用数组 `["第一行","第二行"]` |
| `fontScale?` | 字号，**相对画布宽度**的比例 |
| `weight?` | 字重 100–900。省略用排版方案的正文字重 |
| `align?` | `left`（默认）/ `center` / `right` |
| `curve?` | **弧形排布**：文字沿向上拱的弧线排，值 = 弧顶抬升占容器高的比例（0–1，0.5–0.9 是明显拱形）。整节点合并为单行、水平固定居中。只给标题类短文字用；rect 高度建议 ≥ fontScale × 画布宽 × 2，否则弧顶文字会溢出容器 |

**字号四档**——所有文字都用同一个 `text` 类型，靠**字号 + 字重**拉开层级：

| 层级 | fontScale | weight |
|---|---|---|
| 主标题 | 0.045 – 0.055 | 900 |
| 副标题 | 0.024 – 0.030 | 400 – 600 |
| 标注 | 0.020 – 0.024 | 400 – 700 |
| 脚注 | 0.014 – 0.019 | 400 |

**文字一律不换行**：装不下时渲染器会自动缩小字号——所以你只要保证 `w` 给够。

### `shape` —— 形状（框 / 底板 / 分区）

```jsonc
{ "id": "panel", "name": "右侧底板", "type": "shape",
  "shape": "rect", "radius": 0.3,
  "rect": { "x": 0.55, "y": 0.08, "w": 0.38, "h": 0.84 } }
```

**只有四种形状：**

| `shape` | 是什么 | 典型用途 |
|---|---|---|
| `rect` | 矩形（可带圆角）| 卡片底、底板、分区、斜切图块 |
| `ellipse` | 椭圆 / 圆 | 圆形徽章、大圆、头像位 |
| `arch` | 拱门（上圆下方）| 拱形图窗 |
| `triangle` | 三角形 | 装饰 |

| 参数 | 说明 |
|---|---|
| `radius?` | 圆角：**相对框短边**的比例，**范围 0–0.5**（`0.5` 就已经是完全的胶囊）。**仅 `rect` 有效** |

⚠️ **形状没有"朝向"参数**——想要尖朝下的三角形，就用 `transform.rotate` 转 180°。
⚠️ **想要斜切**（平行四边形）——用 `shape:"rect"` + `transform.skewX`，
**不要**去找一个"平行四边形"形状（它不在列表里）。

## 五、`shape` 怎么当框、当底板 —— 靠**位置重叠 + 顺序**

**「框住一张图」不是数据上的从属关系，而是两个独立节点位置重叠。**

```jsonc
// 顺序很重要：写在**前面**的在**下面**
[
  { "id": "card-bg", "type": "shape", "shape": "rect", "radius": 0.25,
    "rect": { "x": 0.6, "y": 0.2, "w": 0.36, "h": 0.2 } },        // ← 底板（在图下面）
  { "id": "card-img", "type": "image", "asset": "detail.png",
    "rect": { "x": 0.63, "y": 0.23, "w": 0.1, "h": 0.14 } }        // ← 图
]
```

**`layers` 数组顺序 = 叠放顺序**（先写的在下面）：

| 想要的效果 | 形状写在图的… |
|---|---|
| **底板**（垫在内容下面） | **前面** |
| **相框**（压在内容上面） | **后面** |

描边不填充 = 看起来是「框」；填充不描边 = 看起来是「底板」——
*具体颜色、线宽归 `design-appearance.json`，你只决定"这里有一个什么形状"。*

## 六、网格：12 × 12，是**参照**不是约束

排版时**按 12 列 × 12 行思考**，元素的边缘尽量落在格线上——
这样同类元素天然互相对齐。**12 能被 2 / 3 / 4 / 6 整除**，
等分好算：两个各占 6 格，三个各占 4 格，四个各占 3 格。

```
占 1/2   →  x: 0    或  0.5       w: 0.5
占 1/3   →  x: 0    0.333  0.667  w: 0.333
占 1/4   →  x: 0    0.25   0.5   0.75   w: 0.25
```

**四条用法**：

1. **边缘落在格线上**——一栏内容的左边缘统一在 `0.083`（= 1 格），
   就不要有一块写成 `0.09`
2. **一行多个元素用等分**——2 个各 0.5、3 个各 0.333、4 个各 0.25
3. **垂直方向同理**——区块间距取同一个值
4. **重要的占多格**——视觉层次可以直接用「占几格」表达：
   主角占 6–8 格，次要占 2–3 格，标注占 1 格。
   网格还能帮你**规划留白**：刻意空出几格不放东西，画面就透气了。

**为什么较真**：设计里最常见的错误不是"明显错位"，而是**近似对齐**——
两个元素差了 `0.03`，看起来就像没对齐，**比明显错开还难看**。

**但也别死守网格**：它是**参照**。想让画面有张力，可以**故意偏离**——
稍微斜一点、稍微错开一点。**偏离要有意图，不要是随手的偏差。**

### 间距只用这四档

| 档 | 画布比例 | 用在哪 |
|---|---|---|
| `tight` | `0.010` | 元素内部：图标与它的文字 |
| `group` | `0.022` | 同一组内：三行说明彼此 |
| `block` | `0.045` | 组与组之间：标题 ↔ 副标题 |
| `section` | `0.085` | 大区块之间：头部区 ↔ 主要内容区 |

**三条纪律**：同一层级用同一个值 · 不同层级差 2 倍以上 · **不要把间距做平均**。

## 七、排版思想 —— 写 spec 之前，先想这些

下面是**启发式**，不是硬规则。**先把基础版式做对（对齐、间距、层级），再考虑用它们加分**；一次用一两个就够，堆砌会变成视觉噪音。

### 先想清楚：视线怎么走？

画面上的元素不是平等的——眼睛会**按顺序**扫过它们，顺序由尺寸、位置、对比决定。动笔前先回答：

- **主流动**：第一眼看什么 → 然后看什么 → 最后看什么？
- **支流**：可以有次要的浏览路径，但**支线不能喧宾夺主**——次级元素的对比必须明显低于主级。

**阅读节奏由间距和位置控制**：间距小 = 读得快；间距大 = 停顿、喘息。上面的四档间距就是节奏的刻度——`tight` / `group` 让视线连读，`block` / `section` 让它停一下。

### 三个自检问题（写完 spec 后逐个回答）

1. **视线是怎么划过版面的？**——需要跳转，还是平滑过渡？（两种都可以，但要**有意为之**）
2. **相关元素在视觉上分组了吗？**——同类的靠近、用同档间距，别让 related 的东西散开
3. **每个元素是增加清晰度，还是制造视觉噪音？**——说不清它为什么存在，就删掉它

### 层级：字号用倍数，尺寸用黄金比例

**相邻层级的字号成倍数**才有和谐感（如 20 / 40 = 1 : 2）；零散的字号（18 / 26 / 37）会让画面失序。上面的字号四档就是按这个设计的——**同一份 spec 里的字号尽量互成倍数**。

元素**尺寸**同理：**黄金比例（1 : 1.618）** 是最悦目的相邻比——
一块高 0.50，它旁边一块高 0.31（= 0.50 ÷ 1.618）会比随手给的 0.4 更顺眼。

### 杠杠点：一个画面只有一个主角

"杠杠点" = 版面最核心的元素（产品、大标题、让人记住的那个东西）。
突出它的四个手段——**选一两个，不要全用**：

| 手段 | 怎么做 | 在契约里 |
|---|---|---|
| **缩放** | 明显比别的元素大 | `rect.w / h` 拉大 |
| **对比** | 别人都小、都暗，它大、它亮 | 尺寸 + 外观文件的颜色 |
| **定位** | 放在视线落点（中线、三分线交点）| `rect.x / y` |
| **隔离** | **用留白包围它**——它周围空，别的挤 | 间距用 `section` 档围着它 |

### 层次感：让相邻元素**稍微重叠**

完全平铺的版式像表格。让相邻元素**边缘稍微压过彼此**（压 2–6% 画布），画面立刻有前后层次。

做法和「框住」完全一样：两个独立节点 + 位置重叠 + `layers` 顺序定前后。

⚠️ 是"**稍微**"——压住对方一个边角，不是大面积盖住。

### 打破网格：大部分对齐，一个故意不

全部对齐 → 平稳但可能无聊；全部乱来 → 就是乱。
**大部分元素守格 + 一个明显打破** → 冲击力 ✓

那个打破的元素会自动成为焦点——所以**通常让杠杠点去打破网格**，别让次要元素抢这个戏。

### 暗示运动感：静止画面里的"动"

| 手段 | 契约里的表达 |
|---|---|
| **递进** | 同类元素尺寸逐级变化（如三个色块 0.06 / 0.09 / 0.135，≈ 1 : 1.5 : 2.25）|
| **缩放对比** | 一大一小并置 |
| **方向性** | `transform.rotate` —— 让一组元素朝同一方向倾斜 |
| **重复** | 暂缓（等 `repeat` 回来）|
| 模糊 / 运动模糊 | **不做** —— 归生图提示词 |

## 八、⚠️ 不要写什么

### 1. 颜色、描边——归「外观」文件

**不要**出现这些字段（写了会被校验拦下，白白浪费一轮）：

```
fill · color · customColor · textColor · iconColor · background
stroke · ring · edgeLine · edgeHighlight
```

颜色由同目录的 `design-appearance.json` 给，按**节点 id** 索引：

```jsonc
{ "palette": "warm-copper", "fontScheme": "slab-rokkitt",
  "layers": { "panel": { "fill": "#151515" }, "title": { "color": "#FFFFFF" } } }
```

> 为什么分：**草图是灰阶的**。让模型在产版式时被问配色，
> 它只会编出 `cold-dusk` 这类不存在的方案名。

### 2. 光影、材质、效果——归**生图提示词**

**不要把它们做成节点。** 这一条不是风格偏好，是硬边界——因为它们在成品阶段会**真的被画出来**：

| ❌ 不要这样做 | 后果 |
|---|---|
| 加一条"瓶身右侧的高光"的节点 | 成品阶段会真的画出一条直线**压在照片上**，而且对不齐 |
| 给"会由 AI 生成进场景的商品"补接触阴影 | 阴影**已经含在生成的场景里**，再加就是**双影** |
| 铺一个满幅 `shape` 当"深色背景" | **底色是颜色问题**，属外观步骤。有生成图时它自己就铺满 |

### 3. 分不清的三类话

| 方案里说的话 | 归谁 |
|---|---|
| 「标题放在上方居中、占宽 84%」 | **你**（落成 `rect`）|
| 「名字叫 NOIR 07」「底部小字 Eau de Parfum · 50 ml」 | **你**（这是画面文案，逐字落到 `text`）|
| 「深黑背景」「暖色调」「磨砂质感」 | 外观 / 生图提示词，**不写** |
| 「光从右上斜打过来」「瓶身一道细高光」 | **生图提示词，不写** |
| 「一瓶方形香水立在正中」 | **生图提示词**。你只需给它留位置（一个 `image` 节点的 `rect`）|

## 九、一个完整的例子

```jsonc
{
  "name": "DEMO",
  "title": "示例版式：左侧主图 + 右侧信息板",
  "canvas": { "width": 2000, "height": 2000 },
  "layers": [
    { "id": "panel", "name": "右侧信息板", "type": "shape",
      "shape": "rect", "radius": 0.25,
      "rect": { "x": 0.55, "y": 0.08, "w": 0.38, "h": 0.84 } },

    { "id": "hero", "name": "主图", "type": "image",
      "asset": "hero.png", "fit": "contain",
      "rect": { "x": 0.05, "y": 0.15, "w": 0.45, "h": 0.6 } },

    { "id": "title", "name": "主标题", "type": "text",
      "text": "Drei Dinge, die sofort auffallen",
      "rect": { "x": 0.6, "y": 0.15, "w": 0.28, "h": 0.07 },
      "fontScale": 0.045, "weight": 900 },

    { "id": "sub", "name": "副标题", "type": "text",
      "text": "Handgefertigt aus Akazienholz",
      "rect": { "x": 0.6, "y": 0.25, "w": 0.28, "h": 0.035 },
      "fontScale": 0.022, "weight": 500 },

    { "id": "rule", "name": "斜切装饰条", "type": "shape",
      "shape": "rect",
      "rect": { "x": 0.6, "y": 0.34, "w": 0.28, "h": 0.02 },
      "transform": { "skewX": 0.6 } }
  ]
}
```

## 十、常见错误（写之前先看一遍）

| 错误 | 正确做法 |
|---|---|
| 写像素坐标（`"x": 70`） | 一律 0–1 比例，且**都写在 `rect` 里** |
| 把 `x/y/w/h` 写在节点顶层 | 必须写在 `rect` 对象里 |
| 忘了 `id` 或 `rect` | 三类节点都必须有 |
| 用 `box` / `rect` / `text` 之外的 type | 只有三个：`image` / `text` / `shape` |
| 想斜切就去找 `parallelogram` 形状 | 用 `shape:"rect"` + `transform.skewX` |
| 想三角形朝下就去找朝向参数 | 用 `transform.rotate: 180` |
| `transform: {}`（空的） | 至少要有一个 `rotate` 或 `skewX`；什么都不做就整块删掉 |
| `transform` 里只写了 `origin` | `origin` 是支点，必须配合 `rotate` 或 `skewX` |
| `radius: 0.9` | 范围是 **0–0.5**（0.5 已经是胶囊，再大没效果）|
| 给 `image` 写 `fontScale` | 那是 `text` 的字段，两类的字段不要混 |
| 用 `image` 放商品图却写 `fit:"cover"` | 商品图用 `fit:"contain"`，否则会裁到主体 |
| 铺一个满幅 `shape` 当「底色」 | **不要写**。底色是颜色问题，属外观步骤 |
| 把「光从右上打过来」做成节点 | 效果描述归生图提示词 |
| 一个节点想同时表达两件事 | 拆成两个节点（数量没有上限）|
