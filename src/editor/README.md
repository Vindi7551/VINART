# `src/editor/` —— 编辑器层

**设计文档在项目级：[`docs/EDITOR-EVOLUTION.md`](../../docs/EDITOR-EVOLUTION.md)**
（现状调查 + 类 PS 演进方案 + 分阶段验收判据 + 未决问题）。**动本目录前先读它。**

## 一句话

编辑器不住在子文档里，而是**住在父文档**、只把子文档当**被操作对象**的一层。
`iframe` 退化为纯渲染器（`pointer-events:none`、不含脚本），交互由父文档的覆盖层接管。

> ⚠️ **术语（2026-10-16 文档模型改版，先读再读下面）**：文档是三层 —— **画布 → 图层 → 元素**。
> **模型里的 `Layer` 现在专指「图层」**（画布的孩子，效果字段 + `elements: ElementNode[]`，
> **没有 `rect`**），旧的"五类节点联合 `Layer`"已改名为 **`ElementNode`**。
> 本目录沿用的 `LayerDom` / `hitLayer` / `data-layer` / 方法名 `addLayer`/`moveLayer` 里的 "layer"
> 是**历史命名**，实际指的是"文档里一个可命中的容器"——
> 所以本文里凡是说"选中某个**层**""拖这一**层**"，基本都是指**元素**。
> 权威结构见 `src/document/README.md` §一。

## ⭐ 新链画布编辑器 `vocab-editor.ts`

**作用对象是文档（`DesignDocument`），不是 HTML。** 管两类手势：

### 整块（任何节点都有）

| 动作 | 触发 | 落到文档上 |
| --- | --- | --- |
| 移动 | 在**已选中**的层上按住拖（图形**内部**） | `rect.x` / `rect.y` |
| 缩放 | 拖四角**方块**柄（Shift 锁比例） | `rect.w` / `rect.h` |
| 旋转 | 拖顶部**圆**柄 | `transform.rotate` |

### 顶点（只有 `polygon` 有）

| 动作 | 触发 | 落到文档上 |
| --- | --- | --- |
| 拖顶点 | 按住**圆点**拖 | `points[i]` 改了 |
| 加顶点 | **点边上任意位置**（整条边都算，不必瞄准小圆点） | `points` 多一个，**就长在光标指的地方** |
| 删顶点 | **双击**圆点 | `points` 少一个（**保底 3**） |

「加顶点」的位置由**光标投影到那条边**算出（`nearestEdge` 的 `t`）；
那个橙色小圆点只是**跟着光标滑**的提示。边太短（< 26 local px）不给加；
光标压在某个顶点上时不显示它。

**两套手柄并存是刻意的**：**方块**柄（`overlay.ts`）= 动整个框，
**圆点**柄（`point-overlay.ts`）= 动这个形状本身。
明确**不启用**的：顶点编辑遇 `skewX`/`skewY`/`scale` 不显示圆点柄；
旋转遇 `skewX`/`skewY` 不给旋转柄（只带 `scale` 的能转，实时预览走渲染器同一个 `transformCss`）。

### ⚠️ 五个踩实了的坑（别再踩）

1. **`pointerdown` 里不能 `preventDefault()`** —— 它会把随后那次 `dblclick` 一起吃掉，
   双击删顶点就永远不触发。抑制文字选择改在 `mousedown` 里做（同已删除的旧 `index.ts`）。
2. **拖顶点调了 `setPointerCapture`，于是 `click` / `dblclick` 的 `target` 被重定向到 `wrap`**。
   ⇒ **删顶点必须按坐标认顶点**（`nearestVertex`），**不能看 `e.target`**。
   实测事件流：`pointerdown→DIV[vtx=1]` 但 `dblclick→DIV[vtx=null]`。
3. **「加顶点」那个跟着光标滑的小圆点必须 `pointer-events:none`**。
   不然它会盖在顶点手柄上，把 `pointerdown` 的 `target` 抢走 ⇒ **顶点拖不动**（实测位移恒为 0）。
4. **移动和"加顶点"抢同一块地方**：点边时 `hitLayer` 判"在选中的层里" ⇒ 起了移动手势
   ⇒ `click` 被吃掉 ⇒ **加不了顶点**。地盘划分：**边上 = 加顶点，图形内部 = 移动**
   （`pointerdown` 的移动分支要排除 `edgeUnder(p)`）。
5. **方块的角柄会和顶点手柄叠在一起** —— 多边形的顶点**常常正好在盒子角上**。
   角柄默认偏移不够 ⇒ 缩放柄被顶点层（z-index 更高）盖住 ⇒ **点不到**。
   新链把角柄推到 `-20`，并有探针断言"两套手柄中心距 > 半径和"钉住它。

### 文字选区（只有文字有）—— **Word 那样，选中哪几个字就改哪几个字**

| 动作 | 触发 | 落到文档上 |
| --- | --- | --- |
| 进入 | **双击**文字 | `textEditId` = 那个节点（宿主收到 `onTextEditChange`）|
| 选字 | 在画面上**拖**（浏览器原生选区） | 编辑器自己记账（绝对下标），并 `onSelectionChange` 报给宿主 |
| 改样式 | 面板调 `styleSelection(path, value)` | `runs` 在选区两头被切开，**只**中间那段带新样式 |
| 退出 | Esc / `endTextEdit()` | 可编辑性收回、`onSelectionChange(null)` |

**能改哪些样式**由 `inspector.selectionFields()` 描述，当前**十八项** ——
**凡是 Word 字符面板里"选中几个字就能设"的**都在：字号 / **字体** / 字重 / 斜体 / **横向拉伸** / 颜色 /
下划线 / 删除线 / **线色 · 线型 · 线粗** / 字距 / **词距** / 上下标 / 大小写 / 小型大写 /
**OpenType 特性** / **可变字体轴**。
面板值 → `RunPatch` 的换算（**px ↔ 0–1**）在 `selectionFields` 旁边的 `selPatchOf()`。

⭐ **面板只认编辑器给的"选区快照"**（`VocabEditorHandle.selectionSnapshot()`）：
`{ layerId, text, abs, fields: [{ path, label, kind, value }] }` ——
一次算齐、带每项**此刻的生效值**。面板**不碰 `runs`、不知道 `RunPatch`**，
改的时候把 `(path, value)` 递给 `styleSelection()` 就行
（`src/ui/SelectionStylePanel.tsx` 就是照这个契约写的；选区变了编辑器会
`onSelectionChange` 推新快照上去，内部做了指纹比对，不会鼠标一动就重画）。

⚠️ **装饰线是逐项覆盖**：片段只改了线色，线型 / 线粗仍跟随元素级
（不是"整对象替换" —— 否则改一个子项会把另外两个冲掉）。
⚠️ `applyToRange` 落 patch 用的是**浅展开**，而 `decoration` 是**对象** ⇒
`text-session.ts` 的 `mergeDecoration()` 先按"**元素级 ?? 片段**"铺开生效值、再叠本次那一项 ——
少了这一步，元素级那条线型 / 线粗会被冲掉（实测：改完线色只剩 `{color}`）。

⚠️ **开关类写回的是显式 `false`**（"明确不要"），不是"删掉这个键"（"跟随元素级"）——
两者在 `text-runs.ts` 的判等里是**不同**样式。这样才能做到"整块开下划线、某几个字不要"。

⚠️ 这批字段 2026-10-14 才从 `TextNode` 移进 `TextRun`（词汇层修正）：它们本来就是**字符级**的
（Word 里下划线 / 字距 / 上下标全都能只作用于选中文本），留在元素级等于"这个能力根本不存在"。
分工判据见 `vocabulary.ts` 的 `TextRun` 注释：**不是"CSS 能不能"，而是"设计师会不会只想改这几个字"**。

⚠️ 选区字段**故意没有 `set`**：改"选中的几个字"不是"给某字段赋值"，而是**在选区两头各切一刀**
（`text-runs.ts applyToRange`）。硬塞一个 `set(node, v)` 会让调用方以为改的是整块。

#### ⭐ 改完样式，选区不能丢（不然没法连调）

改一次样式 ⇒ 重渲 ⇒ **子文档整个换掉**，`runs` 也被切开（"一段变三段"）⇒
上次记的 `{run:0, offset:5}` 事后指的可能已经是别的字。
⇒ 选区额外记一份**绝对字符下标**（`pointToAbs` / `rangeFromAbs`，见 `text-runs.ts`），
重渲后据此在新 `runs` 上重算，并调 `rangeToSelection()` 把**浏览器的选区也恢复回去**。

不做这一步的后果很具体：调字号天然要连按几次，而每按一次都要重新拖一遍选区。

**为什么不是"点一个词换一个色"**（老 `index.ts` 那条路：每个词一个 span 带 `data-ve-word`）：
Word 里选的是什么就是什么 —— 可以是半个词、可以跨词。**按词点选达不到这个**，
所以这条路走**浏览器原生选区**（`getSelection()`），不照抄老实现。

链路（四站，缺一不可）：

```
emit.ts 给每个片段打 data-run="i"
   ↓
浏览器 getSelection()  →  text-selection.ts 翻译成 {run, offset}
   ↓
text-runs.ts  applyToRange()  两头各切一刀、只给中间上色、相邻同款并回去
   ↓
vocab-editor.ts applyRange()  →  opts.onChange  →  重渲 → rangeFromAbs() 重算选区 + rangeToSelection() 恢复
```

**编辑器不管"让鼠标能落到画面上"** —— iframe 平时是 `pointer-events:none`
（M1 的结论：它是纯渲染器）。进文字态时由**宿主**放开（编辑器只发 `onTextEditChange`），
因为那是宿主的 DOM。

#### ⚠️ 四个坑（都踩过）

1. **Esc 得在子树档上也听一次。** 选字时焦点在 iframe 里，按键**根本不经过父页面** ——
   只在父页面听 keydown，Esc 永远收不到。
2. **`d.write()` 之后是另一个 `Document`，挂在它上面的监听全丢。** 每次重渲都要重新挂，
   否则"第一次能选字、重渲一次就选不动了"。
3. **沙箱 iframe 里不能用 `page.mouse` 拖**（只影响探针，不影响产品）：
   Playwright 开拖拽拦截时要在那个帧里跑脚本，被 `sandbox` 挡住就**整个页面崩**
   （`Blocked script execution … Target crashed`）。三种组合逐一试过：
   有 sandbox + `page.mouse` = 崩；**没** sandbox + `page.mouse` = 正常；
   有 sandbox + **裸 CDP** `Input.dispatchMouseEvent` = 正常。
   ⇒ 是 Playwright 的锅，产品没这问题；探针里改用裸 CDP。
4. **改一次样式就重渲，重渲就把"选区控件"重建一遍 ⇒ 正在输入的那个框被换掉、焦点丢了**
   （想输 "72"，只有 "7" 进得去）。⇒ 宿主侧用一个"这一轮别重建"的开关：
   由选区块自己发起的改动，回来之前跳过重建（控件留着，值就是用户刚输的那个）。

> ⚠️ 还有一条容易忘的语义：**选区起点正好压在段尾时，控件要显示下一段的格式**。
> 例：切开后选区是 `0:5 → 1:5`，它覆盖的只有 `runs[1]` 的前 5 个字 ——
> 问"选中部分多大字号"得看 `runs[1]`。用 `text-runs.ts firstRunOf()`，别看 `from.run`。

## ⭐ 画布上打字（插入编辑）—— **编辑器自己管**（2026-10-15 收回）

双击文字进去之后，**光标、方向键、拖选、输入法全交给浏览器** —— 做法是把 `.vt` 设成
`contentEditable`。自绘光标要重写一遍文字布局量算，不值当。

| 谁 | 管什么 |
|---|---|
| **`text-session.ts`（编辑器）** | 设 `contentEditable` / 聚焦、拦 `beforeinput` 等事件、光标与选区记账、就地补 DOM |
| **宿主** | 只剩两件：① 放开 iframe 的 `pointer-events` ② `flatten` 时重渲一份"摊平版" |

> ⚠️ **这一节早先写的是"由宿主负责"** —— 而老链真的把它放在宿主侧适配器
> （`target.ts` 的 `setEditable`）里。编辑器换新时那条掉了：`target.ts` 变成孤儿、
> `vocab-editor.ts` 里 `contentEditable` 出现 **0 次** ⇒ **生产界面上双击文字根本不能打字**
> （demo 里能用，是因为 demo 宿主自己重写了一遍）。2026-10-15 搬回编辑器，
> 实现照抄 demo 那份已验证的绑定。

```
敲键 → beforeinput（拦下）→ 绝对下标 → text-edit 改 runs
     → 段数没变：**就地补那一段的文字**（patchTextDom）   ← 打字走这条
     → 段数变了：报 `onChange(…, '改文字结构')` 让宿主重渲（结构变了，必须重建节点）
```

**为什么不能每敲一个字都重渲**：重渲 = `emitDocument()` + 换掉整个子文档 ——
光标没了、`contentEditable` 没了、布局重排。打字是**高频**操作，
这么干光标会闪、页面会卡。⇒ 探针里专门有一条钉住"段数没变时没重渲"
（`onTyping` 记了、`onChange` 一次都没记）。

| 敲什么 | 落到文档 |
| --- | --- |
| 普通字符 | 光标处插一段（**继承落点那一段的样式** —— "接着前面继续打"的直觉）|
| Enter | 插一个 `\n`（词汇里"行"是内容，**不产生新片段**）|
| 退格 / Delete | 删前一个 / 后一个；**有选区时先删掉选区** |
| 有选区时打字 | **替换掉选区**（Word 同款）|
| 粘贴 / 剪切 | 一律挡下只取纯文本；剪切先把选中的字写进剪贴板 |
| 从别处拖文字进来 | 直接 `preventDefault`（会让 DOM 与文档分家）|
| 方向键 / Home / End / 鼠标点 | 浏览器管；我们在 `keyup` / `mouseup` / `selectionchange` 把位置记下来 |
| Esc | 退文字态（**子文档上也要听** —— 焦点在 iframe 里时按键不经过父页面）|
| Ctrl+Z / Ctrl+Shift+Z | **拦下**（浏览器的原生撤销改的是 DOM，会把真源搞乱）→ 走编辑器的撤销栈 |

回调 `onTyping(id, doc)` 与 `onChange` 分开：前者意思是"**数据变了但结构没变**，
宿主可以只补那一段、不必重渲"。

### ⚠️ 三个坑（都踩过）

1. **`onTyping` 必须把 `doc` 一起交出去。** 编辑器内部拿的是 `cloneDoc()` 出来的**克隆**，
   宿主手里是另一个对象 —— 不递过去，宿主就会拿着旧副本"把刚打的字又写回去"。
   现象：`insertText` 明明成功、**文档却纹丝不动**（调试时 handler 被调用了、参数全对，就是没效果）。
2. **`domPointInSpan` 对 `<br>` 必须**两边都管**。`<br>` 代表文字里的 `\n`、算 1 个字符：
   位置"落在它前面"贴前、"吃掉了它"贴**后**。只写前一半 ⇒ 光标在末尾时会被放到 `\n` **之前**，
   退格删掉的是前一个正常字符。现象：**"删了个莫名其妙的字，换行还在"**。
3. **`plaintext-only` 不是所有 Chromium 都认。** 属性值看着设上了、`isContentEditable` 却是 `false`
   （现象：点了没光标、打字毫无反应）⇒ 设完**真的检查一次**再退化到 `'true'`。
   ⚠️ 探针要断言可编辑性，读 **`isContentEditable`**，别读属性值（那个会骗人）。

⚠️ **沿路径排字的文字（`curve` / `path`）在编辑期间会被"摊平"**：它最终走 SVG `<textPath>`，
页面上没有 `.vt`、也挂不上 `contentEditable`（SVG 元素没有这个能力，实测）。
⇒ 宿主在**进/出文字态时各重渲一次**，把那个节点的 `path` / `curve` **摘掉再送渲染**
（`src/demo/vector/main.ts` 的 `renderDoc()`），于是它就是普通文字、能打字；
退出时自动回到弧线。

⚠️ **降级只发生在"送进渲染器的那一份"上**（深拷贝）：`doc` 本身一个字节都不改，
编辑器的工作副本也看不到这份降级文档 —— 否则"平铺版"会被写进文档，再也回不去弧线。
⚠️ **代价**：摊平时的宽度 ≠ 弧线上的可用长度（弧长与直线距离不是一回事）⇒
状态条要讲明白"这是摊平显示、最终是沿路径的"，否则用户会照平铺的宽度调字号、退出后被截断。

⚠️ **输入法走单独一条落盘路**：组合期间 `beforeinput` 不可取消（`cancelable = false`），
且 `isComposing` 的 Esc / Enter 归输入法（取消候选 / 选词，不是退出文字态 / 插换行）⇒
组合期间**一律不拦**，只在 `compositionstart` 记下当时的**文档选区**；
`compositionend` 用 `event.data` 在文档上"删选区 + 插上屏文本"，再按文档重渲 DOM。
DOM 回读只作为兜底（没有起点快照 / 没有 data 时），而且只读文字、不读样式。
`compositionend.data` 带串但 DOM 还停在原文 ⇒ 按"取消"处理，不落盘。

## ⭐ 属性面板 `inspector.ts`

**「能改什么」和「怎么画出来」是两件事**，所以分成两层：

- **`inspector.ts`（本层）**：一个节点有哪些可改字段，每个字段带 `get` / `set`。
  **纯描述，不碰任何 DOM** —— 换 React / 换个壳都不用动这里。
- **UI 层**（现在是 `src/demo/vector/main.ts`，将来可以是 React）：
  按 `fieldsFor(node, canvas)` 画一排输入框，改了调 `editor.patch(id, path, value)`。

### 为什么用 `get` / `set` 函数而不是字符串路径

字符串路径（`'runs[0].text'`）看着更"数据化"，但解析起来全是坑（数组下标、字段不存在、类型是联合）。
这里直接用闭包读写 ⇒ **写的时候编译器帮你检查**，跑的时候也不会解析失败。
`path` 只当**标识**（UI 拿它做 key，探针拿它断言）。

### 面板上写 **px**，文档里存 **0–1**

人是按像素想的，文档是按画布比例存的 ⇒ 换算收在 `inspector.ts` 里，
`rect.x` / `fontScale` 在面板上都是 px。

### 文字面板：七个组，以及两处容易漏的地方

`textFields()` 把它分成 **内容 / 字体 / 描边 / 排版 / 沿路径 / 装饰 / 字形** 七组：

⚠️ **两处容易漏的**：
1. **`curve` / `path` 与文字描边**曾经漏过 —— 编译器支持了、面板没入口
   （用户看得见弧线字却找不到在哪儿调）。⇒ 探针里加了**防漏断言**：
   `TextNode` 的每个字段都必须在面板里有入口，加字段忘了加面板就会红。
2. ⚠️ **`curve` / `path` 改的是渲染路径**（普通排版 ↔ SVG `textPath`）——
   若那个节点正在被就地编辑（编辑期间会被"摊平"），改完必须**退出文字态**才看得到弧线效果，
   否则用户以为"改了没反应"。⇒ 宿主在 `fire()` 里对这两个字段自动 `endTextEdit()`。


内容那组是**逐片段**的（切成几段就有几个框）；字体一行给整块默认值，
某几个字单独换字号 / 字重 / 颜色走画布上的**选区**（`selectionFields()`）。

⚠️ 这些字段**全部**在 `emit.ts` 里有对应实现 —— 摆出来的框改了都有反应。
反过来，编译器还翻不出的（`curve` 弧形 / `path` 沿路径排字）**不出现在面板上**。

⚠️ **片段被切开 / 合并之后字段数会变**（单段 ↔ 多段）⇒ 那时必须**重建**面板。
只调 `syncPanelValues` 不够：它只更新已有控件、不会长出新行
（实测：染色把文字切成三段，面板却还是一个"内容"框 —— 新切出来的段没地方改）。

### ⚠️ 刻意**没做**的（不是漏了）

渐变 / 图案 / 多层填充 —— 都要专门的编辑器，是另一个量级的东西。
**不摆一排改了没反应的输入框**，交给代码改。

### 一个坑

`handle.select(id)` 必须 **notify = true**（外部发起的选中，宿主得知道）。
写成 `false` 的话属性面板不会重画 —— 实测调完 `select` 面板还是空的。
内部那次 `select(..., false)` 是"编辑器自己决定选中"，不回灌给宿主，免得绕圈。

## 组（`group`）：怎么选中、怎么移动

### ⭐ 组的"移动"到底是什么

词汇里组**没有 `rect`**，而 `Transform` **故意没有 `translate`**（"平移就是 `rect` 的活"）——
两句话各自都对，**合起来就把"组的平移"判了死刑**（组能整体转、能整体淡出，就是不能挪）。

⇒ 解法（不动渲染模型）：**组的移动 = 把它里面的元素一起搬**（PS / Figma 同款）。
组自己不动（它本来就没有位置），落地时把位移写进每个子元素的 `rect`。

- `collectLeaves(group)` 递归收集真正占地方的节点（组里还能套组）
- 手势会话带 `kids`（各自的 `rect0`）⇒ 移动：各自加同样位移；**缩放也走同一条路**
  （按"相对起始框的位置"缩放）
- 拖拽预览：**给组容器加一层 `translate`** —— 容器铺满画布，等于整组在动，一个子元素都不用碰

### 旋转 / 缩放：组自己的，还是分摊给子元素？

| 手势 | 落在哪 |
|---|---|
| **移动 / 缩放** | **分摊给每个子元素**（组自己不动 —— 它没有 `rect`）|
| **旋转** | **组自己的 `transform.rotate`**（子元素一个都不动）|

⭐ 所以"组的旋转"与"组的移动"在文档层是**两种不同的写法** —— 这不是不一致，而是
"组有 `transform` 但没有 `rect`"这个定义的自然结果。

⚠️ **旋转支点必须用「内容框」（子元素并集，不含组自己的旋转）**，不能用"含旋转的并集框" ——
后者中心会随旋转漂移（拖起来抖）。渲染那边也是绕内容框转的（`groupTransformCss`），两边口径必须一致。

⚠️ **组的 `transform-origin` 要换算**：容器是**铺满画布**的（`100%×100%`）⇒ CSS 百分比是相对**画布**，
而 `transform.origin` 是相对**内容框**的 0–1。（普通节点容器就是它自己的框，本来同源，不用换算。）

### 选中：单击选组，再点一次下钻

`elementById()`（**原名 `layerById`**，2026-10-16 改名；= 词汇表的 `findElement`）是**递归**的：
点组内元素时 `elementFromPoint` 命中的是**最上面的子元素**，组容器在它下面；
而且元素如今藏在 `Layer.elements` 里——**只扫 `doc.layers` 那一层必然"什么都选不中"**
（`doc.layers` 现在装的是图层：图层容器铺满画布、带自己的 `data-layer="<图层 id>"`，
但那是**图层 id**，不是元素 id）。

选中规则（`resolveSelection`，与 Figma / PS 同一套）：
- 点在组里 ⇒ 选中**最外层的那个组**
- 那个组**已经选中了** ⇒ 再点一下就**下钻**，选中被点的元素
- **Ctrl / ⌘ / Alt + 点击** ⇒ 直接下钻（一步到位）

⚠️ **"下钻"这条规则不能拿去判断"起不起手势"**：否则选中组之后再按下去想拖，
会被当成下钻 ⇒ **拖不动**（实测踩到）。手势的地盘只认"光标是不是压在**当前选中的那个东西**上"
（压在它组里的元素上也算）—— 点一下（没移动）仍然是点击 ⇒ 下钻；拖着走 ⇒ 搬整组。

⚠️ 同理，`onClick` 里的 `skip` 只能看 **`pointerMoved`**，不能看"有没有起过手势" ——
"按下不动"也是一次点击。

### 包围盒：子元素并集（含组的旋转）

组没有 `rect` ⇒ 包围盒 = 子元素 `rect` 的并集。
⚠️ 求并集时**要把 4 个角按组自己的 `rotate` 转过去**（`emit` 里是绕**画布**转的）——
不转的话框和内容明显错位，一眼就看得出来。

⚠️ **组带变换时，组里"单个元素"不给拖**：子元素的 `rect` 是画布坐标，而拖拽按**屏幕位移**算，
组转了之后鼠标方向与实际移动方向对不上。⇒ 与"顶点遇 `skew`/`scale` 不给柄"同一处理：
**宁可不给，也不给个别扭的操作**，并把原因**说出来**（`blockReason`，由 `syncOverlay` 统一算 ——
⚠️ 写在 `onPointerDown` 里会被下一次 `syncOverlay` 覆盖掉，UI 永远读不到，等于没说）。
注意：**拖"整组"没有这个问题**（平移按屏幕方向算，组转多少都不影响）。

## 升格：rect / ellipse 也能逐点编辑（Figma 同款，单向）

`rect` 的形状是"框 + 圆角"一个公式——文档里**没有顶点可拖**。要逐点编辑，唯一的办法是把它变成点集。
不在词汇里给 `rect` 加点集（那会引入"点集 vs `rect.w/h` 两个说法"），而是**在用户真的要做顶点编辑的
那一刻转换**（`promoteToPolygon` + `ensureEditablePoly`）：

- `rect` → 4 角点（**圆角丢失**，状态条会说明）
- `ellipse` → **24 点近似圆**（尺寸不大时肉眼难辨，放大看是折线）
- `path` 不升格（`d` 是曲线，多边形编辑不适用——路径编辑是另一个功能）

**机制**：选中 rect/ellipse 就显示**等效顶点**（`editablePoints`——升格的预览，先让你看见顶点在哪）；
拖顶点 / 点边 / 双击删点，三个入口都先升格再走 polygon 的既有编辑链路。
升格发一次 `onChange`（文档类型真的变了），**不改视觉**（形状完全一致），`rect` 原样保留为定位框。
⚠️ 三个入口都要先过 `blocked()`：组带变换时**不许升格也不许编辑**（改了也是错位置）。
⚠️ 升格**单向不可逆**——状态条必须说明（"拖顶点或点一下边 ⇒ 转成可编辑的多边形（不可逆）"）。

## ⭐ 统一编辑栈（M2，`editor-stack.ts`）

**一个栈管所有工具**（验收判据"跨工具混用不乱"）——不是文字一条、图片一条。

**快照式**：文档是纯数据 ⇒ 每条命令存 `{before, after}` 两份克隆；撤销 = 装回 `before` + 重渲。
文档只有十几层，克隆成本可忽略（补丁式/diff 只有文档大到克隆昂贵时才值得）。

**唯一出口**：编辑器内所有编辑动作（`submit()`/`commitTyping()`）在**改完文档之后**压栈
（`before` 取自 `stack.head` —— 上一次提交后的状态镜像）。覆盖：移动/缩放/旋转/顶点（拖加删）/
面板 patch/选区染色/打字/**升格**。

**合并（coalescing）**：`key` 相同 + 时间窗 800ms ⇒ 并成一条——
**打字**（key=`type:<id>`，连打多个字 = 一次 Ctrl+Z 全撤）与**面板连点**（key=`patch:<id>:<path>`）。
换行/改样式/移动等 key 不同 ⇒ 自然断开。⚠️ 新编辑清空重做分支（Word 同款）。

**撤销/重做的落地**：`stackUndo` 返回 `stack.head` 本身 ⇒ 编辑器 `doc = cloneDoc(prev)` **必须再克隆一层**
—— 否则 head 与 doc 同引用，下一次编辑改 doc 连 head 一起改，再下一次 push 的 before 就成了"已改状态"
（实测：撤销后打字，命令的 before 混入了已打的字符）。
⚠️ 撤销时若在文字态先自动退出（文字态里浏览器的"原生撤销"改的是 DOM，会搞乱真源 ⇒ 快捷键必须拦下）。
⚠️ `updateDoc`（宿主整体换文档）⇒ `resetStack`（历史作废）。

**快捷键**：Ctrl+Z / Ctrl+Shift+Z（或 Ctrl+Y）；父文档与子文档（文字态）各一层监听（iframe 内按键不冒泡）。

**探针**：`scripts/_probe-vocab-undo.ts`（纯函数 19 + 浏览器 12：拖动撤销回原位 / 连打一次全撤 /
换行断开 / 混用按序回退 / **升格两条撤两次**）——⚠️ **该探针已删除**，条目留作能力清单。

## ⭐ 图层管理（M3）

**编辑器 API**（全部进撤销栈——M2 机制直接复用）。⚠️ **方法名里的 "Layer" 是历史遗留**：
2026-10-16 文档改成「画布 → 图层 → 元素」之后，它们收的**大多是元素 id**：

- `addLayer(node)` —— 加的是**元素**：追加到**第一个图层**的尾部并选中；一个图层都没有就先建 `layer-1`。
  （⚠️ 临时规则：还没说"该加进哪个图层"；等图层面板做出来应改成"加进当前选中的图层"。）
- `removeLayer(id)` —— 收**元素 id**：用 `containerOf(doc, id)` 找到它**所在的容器**（图层或组），
  从那个 `elements` 里摘掉（删组连组内元素一起）；**也收图层 id**：直接从 `doc.layers` 删掉这个图层。
- `moveLayer(id, up|down|top|bottom)` —— 同样两种：元素在**它所在容器**的兄弟之间换位
  （不再"顶层 splice"：图层里的元素只在同图层兄弟间换，组里的只在组内换）；图层则在 `doc.layers` 的兄弟之间换位。

**demo 图层面板**（`#layers` 列）：新增（`+ 文字`/`+ 矩形`，`data-add` 属性）· 行 = 类型中文名 + id +
**上/下/删**按钮（**倒序**排列——最上层在列表顶部）· 点行选中（**选中组的唯一途径**——画布上点组会下钻）。
⚠️ demo 面板列的是**每个图层里的顶层元素**（`doc.layers` 现在是图层表，直接列它只会看到 `layer-1` 这种名字；
组内元素不单独成行）。真正的 UI（`ui/EditPanel.tsx` 的「图层」页）是**两级清单：图层 ▸ 元素**。

⚠️ **方向语义**：数组**后面的东西画在上面** ⇒ `up`（视觉上移一层）= 与**后一个**交换（i+1）、
`top` = 数组尾。第一版写反过（up=i-1 ⇒"上移"实际下移），实测抓出。图层与元素都遵循这一条。

## 两条不变量（都可机器断言）

### ① `src/editor/` 不引用任何全局网页对象

所有文档对象（**宿主 `Document`、挂载点元素、子文档 root**）都**从参数流入**；
编辑器不认识"当前页面"是谁。

保证的形状要说准：编辑器**碰不到任何没被注入的东西** —— 它没有 `document`、
`window` 可用，所以既到不了父页面的别处，也到不了别的 iframe。
这是**结构性**约束，不是沙箱强制的（沙箱会把编辑器逼回"注入进子文档"的老路，
见设计文档 §4.4）。

```bash
# 必须 0 命中。⚠️ 排除 `from '…'`：import 路径里的 `document`

grep -nE "\b(document|window)\b" src/editor/*.ts | grep -v "from '"
```
