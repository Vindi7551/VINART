# composite —— 合成段（④）

**职责**：把各层按**层栈顺序**合成成一张图（顺序 + 混合模式 + 不透明度 + 蒙版）。

## 今天：这里空着

合成目前由 **Chromium 代劳** —— `.dl` 容器按 DOM 顺序叠放，混合走 CSS `mix-blend-mode`，
最后 `page.screenshot` 一次性完成（见 `../rasterize/blink-renderer.ts`）。

> **实测（2026-10-12）**：容器上的 `isolation:isolate` **不会挡住** `mix-blend-mode`
> 与下层的混合（逐像素比对：开/关隔离的差异 ≈ 0.02，混合本身的差异是它的 263 倍）。
> ⇒ **CSS 合成今天够用**，不需要自建。

## 将来：什么时候才自建

CSS 的合成能力不够用时，两道坎：

1. **混合模式只覆盖 16/27** —— `mix-blend-mode` 缺 `subtract` / `divide` 等；
2. **没有组级混合** —— 一组层整体与下层混合，CSS 做不到。

## ⚠️ 自建合成器**不是抛弃 Chromium**

它只接管"**合成**"这一步；**"矢量怎么变像素"仍然借 Chromium**——
从"一次性截图"变成"**逐层在目标分辨率下栅格化**"，再自己按层栈合成。

> 这样**矢量无损仍然保住**（每层都在输出分辨率下才栅格化），
> 只有**位图部分**受它自己的像素数限制。**这正是 Figma 的模型。**

详见 `docs/HYBRID-RENDERING.md`（§5 变换型流水线、§9 架构结论）。
