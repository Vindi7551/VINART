# bitmap —— 位图能力（流水线之外的第 6 块）

**职责**：**像素缓冲 · 笔刷 · 位图算子**（液化 / 蒙版 / 混合等）。

## 位置约定（重要）

- 本模块是**叶子**：**不依赖本项目任何其他模块** ⇒ 可独立测试、独立演进。
- 反过来，`src/document/` 会**引用本模块导出的「位图内容」类型**
  （层的 `kind` 之一：声明式 / 位图）—— 即 **`document → bitmap` 单向依赖**。
- 它**不属于渲染流水线**（`src/render/` 的 ②③④）：流水线负责"把文档画出来"，
  本模块负责"位图本身怎么产生与运算"。

## 今天：这里空着

位图内容**尚未进入契约**。它对应"三层射程"里的第 ③ 层：

| 层 | 内容 | 谁产出 | 留在 DOM？ |
|---|---|---|---|
| ① 声明式 | 形状 / 路径 / 文字 | LLM | ✅ 今天 |
| ② 程序化生成 | 笔刷掩版、撕边、位移图 | 确定性代码 | ✅ 仍渲染在 DOM |
| ③ **光栅** | 实时笔刷、像素累积、液化 | 人（编辑器）+ GPU | ❌ **落这里** |

> **② 层已有实测**（`scripts/_probe-dom-capability/06-programmatic-gen.html`）：
> 6 个场景全部由算法算数据 + SVG 渲染，且**确定性可复现**（同页渲染两次逐像素相同）。

## 将来落这里的东西

像素缓冲 · 笔刷引擎（含压感） · 位图算子（液化 / 操控变形 / 内容识别） ·
与"自建合成器"（`../render/composite/`）对接的像素接口。

⚠️ **一条已知约束**：位图层**必须在输出分辨率下产出**（它是格子，输出放大就糊）——
即"**最大分辨率取决于所有被光栅化的东西里最低的那个**"。

详见 `docs/HYBRID-RENDERING.md`。
