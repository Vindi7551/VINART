# 素材订单与生图提示词

调 `generate_assets` **之前**读这一份。它只落盘文件、**不改 doc**；
生成后要用 `patch_doc` 把节点的 `asset` 指到文件名，画面才会刷新。

## 订单字段

`images[]` 每张：

- `file`：**`.png` 纯文件名**（如 `slot-hero.png`，不含路径）。它同时是 doc 里
  `asset` 的引用键——名字对不上，图就没人用。
- `prompt`：非空；写法见下。
- `size`：`宽x高`（`2048x2048` / `1440x2560` / `2560x1440`），或 `2K` / `3K` / `4K`。
  像素数**不能低于 3,686,400**。
- `references`：参考图文件名数组，**最多 14 张**，一般 1–3 张就够。
  - 相对**版式目录**：`detail.png`
  - 相对**工作目录**：`uploads/chat-xxxx.png`（用户贴的商品照）
  - **没有 role 字段**。哪张是干什么的，写在 prompt 里。

`icons[]` 每张：`{ file, svg }`，是你自己写的线框 SVG，约定：

```
viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"
```

`svg` 节点的 `fill` 用来染色（内部靠 `currentColor`）。

## 参考图：`[图片1]` 指代

在 prompt 里直接写 `[图片1]` / `[图片2]`（也认 `[Image 1]`），指第几张参考图：

> 「[图片1] 是商品照：外观、雕刻、瓶盖必须与之一致，然后在场景里重拍，
> 别把照片贴进画面；[图片2] 只取纹理。」

- 发送前会被编译成「第 1 张（文件名）」；**生图模型不认识方括号记号**。
- 参考图文件不存在会被丢掉，**后面的编号会前移**——所以编号按你写的
  `references` 原始顺序算，编译时自动换算。
- 指不到的编号会原样保留并记 warning，不会让整张单失败。

## 提示词怎么写

当前接的是**指令型**模型（seedream）：完整自然语言句子，按七要素组织：

1. **主体**——是什么（可带需要模型注意的细节）
2. **动作与状态**
3. **场景**——发生在哪里、主体怎么和环境接触（地面/接触阴影/环境光/透视）
4. **风格与媒介**——什么质感的照片（商业产品摄影 / 胶片…）
5. **光线与色调**——光源方向与色温（左侧柔光箱 / 暖钨丝灯＋冷蓝阴影…）
6. **构图·镜头**——机位、焦段、景深（45° 俯视 / 85mm f/1.8 / 浅景深 / 留白）
7. 技术参数**不写进 prompt**：`size` 是独立字段

**禁则**（指令型不认标签权重）：

- 权重语法 `(red dress:1.4)` / `marble::2` **无效**——用「以…为主」的表述
- 质量词堆砌（masterpiece / best quality / 8k）**有害无益**
- 负向词**不需要**，而且实测基本无效

## 怎么写得不单调（反模板）

同一个模型、同一个句式写十张，成品就会像一个模子。每张至少换 **2 个**维度：

| 维度 | 可选 |
|---|---|
| 视角 | 平视 / 低角度 / 俯视 / 过肩 / 微距 |
| 光线 | 窗边侧光 / 逆光 / 黄昏 / 阴天 / 直闪 |
| 镜头 | 24mm 环境 / 50mm 自然 / 85mm 人像 / 100mm 微距 |
| 构图 | 留白 / 三分 / 对角线 / 框架式 |
| 情绪 | 清晨安静 / 夜晚热闹 / 日常杂乱 / 克制 |

### 把形容词换成物理事实

| 不要写 | 改写 |
|---|---|
| 高级感 | 厚壁陶瓷、哑光釉面、桌角有使用痕迹 |
| 氛围感 | 左侧窗光斜切进来，桌面拉出长影，阴影带一点蓝 |
| 太干净、太完美 | 杯口半圈咖啡渍、桌面细划痕、亚麻布自然褶皱、皮肤毛孔 |
| 电影感 | 50mm、f/2、浅景深、背景虚成暖灰 |

真实感三件套：

- **材质**：磨砂 / 釉面 / 织物纹理 / 木纹 / 水汽 / 磨损 / 灰尘；
- **光线**：光源方向、色温、光比、阴影软硬、接触阴影；
- **镜头**：焦段、光圈、景深、机位、透视。

### 张力：每张至少一个「视觉锤」

真实感不等于平淡。每张图至少选 **1 个**强点，并把它写成物理事实：

| 类型 | 具体写法 |
|---|---|
| 硬光 | 单盏硬质聚光灯从左上方直打，影子边缘清晰 |
| 逆光 / 轮廓光 | 背后一盏冷白灯勾出边缘，正面几乎压暗 |
| 深阴影 / 低 key | 大面积暗部，只有主体一侧被照亮 |
| 色片 / 色彩对撞 | 右侧深红亚克力反光，冷白主光形成冷暖对撞 |
| 低角度 / 广角 | 24mm 贴近地面仰拍，主体压向画面 |
| 前景遮挡 | 前景一截虚化的铁链 / 玻璃 / 布料 |
| 动态 | 快门 1/15 拖出轻微运动模糊，主体保持清晰 |
| 氛围介质 | 空气里有薄雾 / 水汽 / 粉尘，光束可见 |

**「效果词」和「质量词」要分开**：

- 禁（空泛、对模型无效）：`8k` / `masterpiece` / `best quality` / `ultra detailed`；
- 可用（具体的光与物）：`hard key light` / `direct flash` / `rim light` /
  `deep shadow` / `low-key` / `color gel` / `practical light` / `haze` /
  `specular highlight` / `motion blur`。

### 对照

单调：

> 一杯咖啡放在木桌上，暖光，高级感，电影感。

改写：

> 清晨六点的厨房窗边，一只厚壁陶瓷杯放在有细划痕的橡木桌上，杯口还留着半圈咖啡渍；
> 左侧窗光斜切进来，在桌面拉出长影，杯壁高光偏冷，桌下阴影带一点蓝；
> 50mm 镜头，f/2，略微俯拍，背景的亚麻窗帘虚成一片暖灰。

高张力改写（同样具体，但光更硬、对比更强）：

> 夜晚的混凝土墙前，一只无标签的磨砂黑玻璃瓶斜放在潮湿石台上，瓶身只有一道冷白轮廓光；
> 左后方一盏硬质聚光灯把影子拉得很长，右前方一块深红亚克力板反射出窄窄的红边；
> 24mm 低角度，前景一截虚化的铁链，空气里有轻微雾气。

### 有参考图时

- `[图片N]` **是商品照**：先锁保真（形状 / 材质 / 标签 / 颜色），再换场景、光线、镜头；
- `[图片N]` **是风格参考**：只取光线 / 色温 / 构图 / 质感，不复制具体内容；
- 用参考图时也别只写「同参考图」——把**要保留什么、要改变什么**说具体。

### 不要

- 只写「高级感 / 氛围感 / 电影感」这类空词；
- 每张都套同一个「主体 + 动作 + 背景 + 光线」句式；
- 一张图写两个画面任务——**一张只讲一件事**；
- 为了“不一样”而每张换风格——同套图锁**色温 / 背景基调**；主角图可以有更强光比，细节图可以更柔；
- 为了“真实”而关掉所有效果——真实感是材质和光的行为，不是低对比；
- 每张都柔光 / 浅景深——那也是一种模板。

## 内容规则（硬）

- **除平台强制纯白的主图外，不要写白底 / 灰底 / 摄影棚布光**——成品会像电商图集。
  环境要具体（木质门廊 + 落叶 / 门口暖光地毯），光线要「有来源」（窗外斜射的午后光 /
  暖色室内灯），不要 `unstyled plain background` / `studio lighting`。
- 需要「干净背景」用**浅景深的真实环境**（虚化的店内 / 木墙），不要纯色渐变。
- **不要下只画背景的订单**（`bg-*` / `leaf-bg` / 「只有纹理 / 满幅底纹」）：
  ① 它必然和主体叠，成品会露矩形边界；② 背景越空，模型越要往里加东西。
  要环境让主体素材自带；要底色交给 HTML/CSS（`shape.fill`）。
- **内嵌细节图**：别写「深色 / 黑底、独立背景」的图直接浮在主图上（会变成黑框）；
  要么写「主体延伸到画面边缘 / 贴边裁切」，要么写「与主图同一场景 / 浅色桌面」。
- **同套图一致性**：锁**色温 / 背景基调**；主角图可以有更强光比，细节图可以更柔——
  “同一次拍摄”不等于每张一样亮。

## 保真声明（用商品照时）

提示词里要有**保真表述**，否则模型会擅自改 logo、增删部件：

> keep the shape, lid, label and color exactly the same, do not add extra text or graphics

**保真的是形状 / 材质 / 标签 / 颜色，不是参考图的平光**——要在场景里重新打光，
该硬就硬、该压暗就压暗，不要连参考图的均匀布光一起抄。

## 结果与重画

- 每张返回 `ok` / `skipped` / `error` / `warnings`；先读错误再改。
- **同名文件默认跳过**（`skipped: true`，不重画）；真要重画同一张，传
  `overwrite: true`。
- `file` 必须是新的 `.png` 纯文件名；重复会被入参校验拒绝。
