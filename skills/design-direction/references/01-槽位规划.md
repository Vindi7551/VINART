# 01 · 图槽位规划

> 读这份的时机：**每次开始设计之前**。这是"不单调"的第一道闸门。
> 槽位不是 listing 专属——任何版式只要承担「证明 / 展示」，就需要一个独立图槽位。

## 一、什么是图槽位

**图槽位 = 画面里一个独立成块的图片位置。** 它不是一个"装饰"，而是回答一个具体问题：
主体长什么样？细节怎么样？用在哪？给谁？凭什么信？

**一张图 = 一个信息任务 ≠ 一个元素。** 一个任务可以拆成多个图槽位；
但**一个槽位只能回答一个问题**。

## 二、槽位的六种角色

| 角色 | 回答的问题 | 典型内容 | 建议占比 |
|---|---|---|---|
| `hero` | 这是什么 | 主体完整呈现，正面 / 45° / 俯视 | 45–65% |
| `detail` | 凭什么信 | 材质、接口、工艺、结构的特写 | 15–25% 每个 |
| `scene` | 用在哪 / 给谁 | 使用中的环境，有接触阴影和环境光 | 20–35% |
| `evidence` | 凭什么比 | 对比 / 前后 / 尺寸参照 / 步骤 | 20–30% |
| `texture` | 什么质感 | 纹理、纸感、光影局部 | 10–20% |
| `logo` | 谁做的 | 品牌 / 认证 / 徽章 | ≤10% |

一套设计不必六种都有。**但只要有"证明"性质的内容，就必须有 `detail` / `evidence` 槽位**，
不能退化成"文字标签"。

## 三、数量纪律

| 槽位数 | 什么时候可以 | 必须做的事 |
|---|---|---|
| **0** | 纯文字海报（引言 / 展览信息 / 大字报） | 说明"为什么不需要图" |
| **1** | 只有单主体、没有可拆的证据 | **写明"为什么不能拆"** |
| **2+** | 有几个独立任务就几个（图集 / 多卖点也一样） | 确认每个都有独立任务，不是凑数 |

**没有「默认档位」**——槽位数由上面的独立任务数决定，不要按 2–3 去凑。

**每个槽位后面都要一次生图**（本 skill 默认不复用裁切）。所以：

- 一张设计几个槽位 = 几次生图；
- 一套 8 张 × 每张的槽位数 = 总生图数；
- **先砍槽位数，再谈构图**。

## 四、槽位表（先给用户看，再画草图）

> ⚠️ **硬门**：槽位表没发出去，**不许调 `sketch_plan`**。
> 用户说「直接做 / 不用问」时也一样——先发一条表，再画草图；表是给用户拦"又只有一张图"的机会。

| 槽位 | 角色 | 画面任务（出现什么，不是"氛围"） | 素材来源 | 占画面 | 框的宽高比 |
|---|---|---|---|---|---|
| A | hero | 产品完整呈现，正面，浅木桌面 | 生图 | ~55% | 4:5 |
| B | detail | 杯口与手冲滤杯特写，侧光 | 生图 | ~20% | 1:1 |
| C | scene | 清晨厨房窗边，杯在桌上，有蒸汽 | 生图 | ~25% | 4:3 |

**"画面任务"必须能直接变生图提示词**，写法是四件事：

```
主体 + 视角 + 背景 + 光线
```

反例：「温暖的氛围」「高级感」「有设计感」——这些不是画面任务，模型只能猜，猜出来就是白底。
正例：「一只白瓷手冲杯，45° 俯拍，浅木桌面，左上窗光」。

## 五、素材策略（本 skill 的默认）

- **每个槽位一张独立素材**，不做"同一张图换个框裁切"；
- 素材文件名与槽位名一致：`slot-hero` → `slot-hero.png`；
- 生图尺寸按**槽位框的宽高比**选（4:5 → 1440×1800；1:1 → 1440×1440；16:9 → 1920×1080）；
- 草图阶段所有图槽位用 `@placeholder`；多个槽位会显示多个**相同的灰色占位图**，这是正常的，素材阶段会替换；
- `generate_assets` 一次可以放多张订单，但每张都要单独写清「主体 + 视角 + 背景 + 光线」。

## 六、反例（出现任意一条就不合格）

- 一张主图 + 一堆文字，没有第二个图槽位；
- 用 `shape` 色块 + 文字标签冒充 `detail` / `evidence`；
- 两个槽位是同一张图换个框（任务重复）；
- 槽位名是 `image1` / `image2`，看不出角色；
- 槽位表里写「氛围图」「高级感」，写不出画面里到底出现什么；
- 先画完草图才想起"好像该有细节图"——顺序反了。

## 七、按版式类型的槽位建议

| 类型 | 建议槽位 | 说明 |
|---|---|---|
| 产品海报 | hero + detail + scene | 常见组合；detail 证明质感，scene 证明使用 |
| 品牌/活动海报 | hero + scene 或 0 | 氛围型可以 1 图 + 大字；信息型按信息量加槽位 |
| 落地页头图 | hero + evidence 或按任务拆 | 产品 + 使用场景，或产品 + 对比 |
| 信息图 | hero + 每个论点一个 detail/evidence | 每个论点一个槽位，不要用文字牌 |
| 杂志封面 | 1（人物/主体） | 靠标题与留白做层级，图不必多 |
| 菜单/价目 | 0–2 | 菜品特写优先于装饰图 |
| 社媒方图 | 1–2 | 手机上读，槽位再多也看不清 |

## 八、和 listing 的关系

listing 不是另一套逻辑：先按本文件做「这张图几个槽位、各讲什么」，
再用 listing 的内容与合规规则去填每个槽位的内容。
**槽位规划是通用的，listing 只负责内容与顺序。**
