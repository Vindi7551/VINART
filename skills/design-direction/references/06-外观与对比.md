# 06 · 外观与对比

> 读这份的时机：**草图定稿之后**（`patch_doc` 阶段）；或用户说"配色不好看/太素/没重点"时。
> 草图阶段**不写颜色**——`sketch_plan` 只决定结构；颜色、字体、对比在这里做。

## 一、外观只做四件事

一个画面只需要四个颜色角色，多一个都会乱：

| 角色 | 作用 | 占比 | 例 |
|---|---|---|---|
| **背景** | 定调，退到后面 | 60–70% | `#F7F3EA` 米白 / `#0E0C24` 深底 |
| **墨色** | 主文字，最高对比 | 20–25% | `#1A1A1A` / `#F5F0E6` |
| **强调** | 主角 / CTA / 关键数字 | 5–10% | 一个暖色或冷色 |
| **弱化** | 注记 / 分隔 / 次要信息 | 5–10% | 墨色的 40–60% 亮度 |

**60-30-10 原则**：背景 60、墨色 30、强调 10。强调色多了 = 没有强调。

## 二、对比的六种类型（都服务于层级）

| 类型 | 怎么做 | 用在哪 |
|---|---|---|
| **明度对比** | 深底浅字 / 浅底深字 | 主文字，保证可读 |
| **色相对比** | 冷底 + 暖强调（或反过来） | 让主角跳出来 |
| **饱和度对比** | 大面积低饱和 + 小面积高饱和 | 强调色只在主角上 |
| **面积对比** | 大块安静 + 小块强烈 | 主角占比小但更亮 |
| **冷暖对比** | 背景冷、主体暖 | 产品/人物更突出 |
| **虚实对比** | 背景压暗/去饱和，主体清晰 | 主图压在图上时 |

**对比不是花哨，是让主角被看见。** 如果每个元素都在对比，等于没有对比。

## 三、三个方向（给用户选，不要开放式提问）

| 方向 | 背景 | 墨色 | 强调 | 字体搭配 |
|---|---|---|---|---|
| **编辑感** | `#F7F3EA` 米白 | `#1A1A1A` | 一个暖色（赭石/砖红） | `Noto Serif SC` 标题 + `Noto Sans SC` 正文 |
| **冷科技** | `#0E0C24` 深底 | `#F5F0E6` 浅字 | 冷紫 / 青 | `Noto Sans SC` 700 标题 + 400 正文 |
| **暖生活** | `#FDF8EF` 奶油 | `#3B2E25` 深棕 | 橙 / 绿 | `Noto Serif SC` 标题 + `Noto Sans SC` 正文 |

⚠️ **中文文字只能用系统注记【字体库·中文】里的 family**（当前：`Noto Serif SC`、`Noto Sans SC`）。
【字体库·仅英文】里的 `Bitter` / `Arvo` 等没有中文字形，写中文会 fallback，出图可能不报错但字形是错的。

字体最多**两个字族**：一个 display（标题）+ 一个 text（正文）。
标题用 600–900 字重，正文 400；**不要正文也用 900**——层级会糊。

## 四、文字压在图上：必须给可读性

- 图上有文字时，先加**压暗层**（`scrim`）：一个 `rect` 覆盖文字区，
  `fill: rgba(0,0,0,.55)`（浅底图用 `rgba(255,255,255,.6)`）；
- **不要用灰色实块**——灰块会变成"贴纸"，不是压暗；
- 文字与背景的对比度目标 **≥ 4.5:1**（正文）；标题可以略低，但不能糊；
- 压暗层要**只盖文字带**（通常 `.30–.45`），不是盖满全图，更不要 `.60` 把主体一起压掉；
- **优先用渐变**：`fill: linear-gradient(to bottom, rgba(20,12,6,.85), rgba(20,12,6,0))`
  （`fill` 支持 CSS 渐变字符串；整块 rgba 会在边缘留一条硬边）。
- **深色细节图放在暗背景上会糊在一起**：优先把它移到亮区（窗户 / 浅墙），
  或在图下面垫一个稍大的浅色 `shape` matte（米白）当框——不要指望阴影（`patch_doc` 不支持）。

## 五、`patch_doc` 能改什么（外观阶段）

白名单：

```
fill           颜色 / rgba(...) / CSS 渐变字符串（linear-gradient / radial-gradient，含 repeating）
stroke.paint   描边颜色
fontFamily     字体族
fontSizePx     字号（px，patch 阶段才用）
weight         字重 100–900
italic         斜体
letterSpacing  字距（em）
lineHeight     行高（倍数）
wrap           normal / nowrap
text           纯文本（单 run）
asset          素材文件名（image / svg）
```

**改不了**（不要假装能改）：

| 想要 | 现状 |
|---|---|
| 旋转 / 斜切 | `rotate` 仅 image/svg/shape（patch 支持）；斜切/文字旋转用编辑器 |
| 圆角 / 阴影 / 混合模式 | `patch_doc` 不支持；编辑器里调 |
| 透明度 | ✅ `opacity` 0–1（patch 支持） |
| 移动 / 缩放 | ✅ `move` / `size`（0–1 比例，patch 支持）；也可以编辑器里拖 |
| 加 / 删元素 | `patch_doc` 不支持；新开一个 layout，或编辑器里加 |

> **渐变是例外**：`fill` 支持 CSS 渐变字符串（`linear-gradient` / `radial-gradient`，
> 含 `repeating-` 变体），不是独立字段，直接传字符串即可。
> ⚠️ **`conic-gradient` 与网格渐变不支持**（SVG 无原生对应，emit 会报 `unsupported`）。

## 六、把颜色接到层级上

1. **背景**最安静：低饱和、低对比；
2. **墨色**最高对比：正文可读；
3. **强调**只给杠杆点：主角、CTA、关键数字——**不要给每个标题都上强调色**；
4. **弱化**给注记：日期、地点、脚注，别和正文抢；
5. 一套图共享同一个 palette：换图不换色，观众才认得出是"一套"。

## 七、白底纪律

- listing 主图：纯白底、无文字（平台硬约束，见 `amazon-listing`）；
- 通用设计：**不要默认纯白**——米白 / 奶油 / 浅灰都比纯白有温度；
- 纯白只在"产品本身是白底、要极简"时用，而且要用**留白和层级**撑住，不能靠"空"。

## 八、自检

1. 四个颜色角色齐了吗？强调色是不是只出现在主角/CTA 上？
2. 文字压图时有没有 scrim？对比度够不够？
3. 字体是不是只有两个字族？正文有没有被标题字重污染？
4. 一套图里，背景/墨色/强调是不是同一套？
5. 有没有为了"丰富"给每行换颜色？（有就删回四角色）
