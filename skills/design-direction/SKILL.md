## 设计导向 skill（索引）

**这不是字段说明书。** 字段与工具用法在 assistant-system；这里管**设计判断**：
一张图 = 一个信息任务；图槽位是「证明 / 展示」的单位；一个画面只有一个主角。

> 视觉气质/风格方向（杂志感、极简、奢华、复古、街头、自然、科技）见 **`design-style`**；
> 本 skill 只负责槽位、recipe、层级与构图。先定风格，再选 structure。

**本 skill 是分层结构**：这份 `SKILL.md` 只是索引 + 主流程，细节都在 `references/` 里。
**用到哪份读哪份，不要一次全读**——读法：

```
skill({ name: 'design-direction', file: 'references/04-杠杆点.md' })
```

### 主流程（四步）

| 步 | 做什么 | 细节 |
|---|---|---|
| 1 | 内容分层：钩子 / 主体 / 证据 / 场景 / 收口 | 本文 §1 |
| 2 | **图槽位表**（硬步骤，先给用户看） | `references/01-槽位规划.md` |
| 3 | **选构图 recipe**（照抄骨架，不手写坐标） | `references/02-构图recipe.md` |
| 4 | 草图之后：**层级 / 杠杆点 / 运动感 / 外观对比** | `references/03`–`06` |

---

### §0 先问清（最多 3 个问题，别审问）

1. **投在哪 / 什么比例**——`1:1` 社媒方图 · `4:5` 海报/信息流 · `3:4` 印刷感 · `16:9` 网页头图 · `9:16` 竖屏故事。
2. **必须出现的文案**——标题、品牌、日期/价格、必须逐字保留的句子。
3. **有没有产品照 / 参考图**——决定素材是「生图」还是「用现成图」。

不要问「你想要什么风格」这种开放题；给 2–3 个方向让用户选（见 `06-外观与对比.md`）。

---

### §1 内容分层（在对话里写，不落盘）

拆成 **3–5 块**，每块标一个角色：

| 角色 | 回答的问题 | 通常是什么 |
|---|---|---|
| 钩子 | 为什么停下来看 | 主标题 / 一句狠话 |
| 主体 | 这是什么 | 图槽位（hero） |
| 证据 | 凭什么信 | 图槽位（细节 / 特写 / 对比） |
| 场景 | 用在哪 / 给谁 | 图槽位（场景）或一句注记 |
| 收口 | 下一步做什么 | 副标题 / 日期 / CTA / 落款 |

**一个版式只承担一个主动作**；第二个动作放副标题，第三个放注记。块数超过 5 就是没分层——先砍，再画。

---

### §2 图槽位（硬步骤）

**槽位数 = 独立任务数**：每个需要「证明 / 展示」的任务一个槽位；0 图只允许纯文字海报；
只有 1 个时写清「为什么不能拆」。没有「默认档位」——不要按 2–3 去凑。
**每个「证明 / 展示」块必须是图槽位**，不能用 `shape` + 文字冒充。
**每个槽位一张独立素材**（不复用裁切）；所以先在槽位表上砍数量。

> ⚠️ **硬门**：在槽位表发给用户之前，**禁止调用 `sketch_plan`**。
> 用户说「直接做 / 不用问」时，也先发一条消息列出槽位表（不需要等回复，但表必须发出去）。

槽位表的列、角色、素材策略、命名、反例、示例，全部在：
**`references/01-槽位规划.md`**

---

### §3 构图 recipe（7 选 1）

| recipe | 图槽位 | 长相 | 适用 |
|---|---|---|---|
| `type-only` | 0 | 纯文字 + 细线 | 引言 / 展览信息 / 大字报 |
| `hero-overlay` | 1 | 满幅主图 + 压暗 + 大字 | 氛围 / 单主体 |
| `split-panel` | 1 | 左文右图 | 引言 / 单主体 + 信息 |
| `diptych` | 2 | 两张等大并排 | 对比 / 前后 |
| `full-bleed-inset` | 2 | 满幅主图 + 细节内嵌 | 质感 / 工艺 |
| `triptych` | 3 | 主图 + 两张细节 | 工艺 / 多证据 |
| `editorial-grid` | 4 | 大图 + 三小图 | 多卖点 / 图集 |

**完整 0–1 骨架坐标、比例换算、变体、选择纪律**都在：
**`references/02-构图recipe.md`**

> 槽位数按**内容任务**选（0–4 都可能）；`type-only` / `hero-overlay` / `split-panel` 只用于确实只需要一个主体的场景。
> 同套图 **recipe 必须错开**，同一 recipe 连用不超过 2 张。
> ⚠️ **满幅图先看素材的安静区**：文字放在画面的暗部 / 天空 / 桌面，不要默认放顶部；
> 主体在中间时用 `full-bleed-inset` 的 **text-bottom** 变体（见 02），别用顶部 scrim 把主体压掉。

### §4 草图之后：把画面做出主次

这四个是「不单调」的真正来源，按顺序用：

| 要解决的问题 | 读哪份 |
|---|---|
| 画面平、散、没有层级；不知道谁是主角 | **`references/04-杠杆点.md`** |
| 视线乱、间距平均、元素平铺、太"表格" | **`references/03-排版思想.md`** |
| 画面太静、像说明书 | **`references/05-运动感.md`** |
| 配色 / 字体 / 对比 / 压暗 / 白底 | **`references/06-外观与对比.md`** |
| 提交前自检 | **`references/07-自检与反模式.md`** |

五条要点（全文见各文件）：

1. **一个画面只有一个主角**（杠杆点）——用缩放 / 对比 / 定位 / 隔离里的**一两个**，不要全用。
2. **层级 ≠ 尺寸**——尺寸只是六个杠杆之一；隔离与装框同样能提升层级。
3. **相邻层级字号成倍数、尺寸用黄金比例、间距不要做平均**——节奏来自"有的地方挤、有的地方停"。
4. **运动感是设计意图**——递进 / 缩放对比 / 方向性 / 重复；方向性需要旋转（当前草图不接收 `transform`，落地方式见 05）。
5. **文字不是只能白字**——标题压图时，描边 / 阴影 / 渐变填充 / 超大字号该上就上；
   每个层级最多加 1–2 种，正文不加。

#### 三个检查点（硬性，不许跳过）

1. **选完 recipe、画坐标之前**：读 `04-杠杆点.md`，用一句话写出「主角是 X，因为 Y」；写不出来就还没设计。
2. **写完坐标、调 `sketch_plan` 之前**：读 `03-排版思想.md`，检查 title/subtitle 是不是 `group` 档（.022）、区块之间是不是 `section` 档（.085）、有没有"近似对齐"。
3. **`patch_doc` 之前**：读 `06-外观与对比.md`，检查四角色、强调色是否只给主角、文字压图有没有 scrim。

> 这三步是**必须读**，不是"按需"。漏掉第 1 步会出现"recipe 对了但画面平"，漏掉第 2 步会出现"标题和副标隔了 100px 还说是紧贴"，漏掉第 3 步会出现"配色每行一个颜色"。

### §5 执行顺序

1. 内容分层 → **先发槽位表**（给用户看；未发出不调 `sketch_plan`）。
2. 选 recipe → 照抄骨架坐标 → **读 04 写「主角是 X」→ 读 03 查间距档差**。
3. `sketch_plan(plan, layout)`：`layout` 必须是**新名字**；有 error 级 issue 就按它改，不要忽略。
4. 素材：**每个槽位一张图**，一次 `generate_assets` 可放多张，提示词逐槽位写清「主体 + 视角 + 背景 + 光线」；文件名与槽位同名。
5. `patch_doc`：先把每个 image 节点的 `asset` 指到文件名，再按 `06` 批量改颜色 / 字体 /
   **文字效果**（fill 渐变、stroke、shadow、runs）；位置 / 尺寸 / 变换也用 `patch_doc`：
   `move {dx,dy}`、`size {w,h}`（0–1）、`rotate` / `skew` / `scale`（仅 image/svg/shape）、`opacity`。
   ⚠️ `patch_doc` **不能新增 / 删除 / 复制节点**；要改结构只能新开一个 layout 或在编辑器里做。
6. 请用户看草图；告诉他用了哪个 recipe、几个槽位、主角是谁、下一步可调什么。

> ⚠️ `sketch_plan` **只新建**：必须传一个**新**版式名，已存在会报错，不再覆盖当前 active。
> 改现有版式的位置/尺寸/颜色/素材用 `patch_doc`；只有结构真的变了（加/删/复制元素）
> 才用新名字再开一版。已有 active 时新建只进画廊，不抢预览。

---

### §6 三条铁律

1. **先槽位，后构图，最后外观**——顺序反了就会退化成"一张图 + 文字堆"。
2. **一次只用一个杠杆点手段的一两个**——堆砌会变成视觉噪音。
3. **说不清它为什么存在的元素，删掉**——每个元素要么增加清晰度，要么就是噪音。
