## 设计导向 skill（索引）

**这不是字段说明书。** 这里只管**设计判断**：
一条信息 = 一个任务；一个画面只有一个主角；形式（文字/照片/图形）是内容的结果，不是起点。

> 原始素材/文本先见 **`source-analysis`**：它读事实、形式、语义、联想、氛围，输出 source brief；
> 视觉气质/风格方向（杂志感、极简、奢华、复古、街头、自然、科技）见 **`design-style`**；
> 本 skill 只负责内容清单、构图、层级与结构判断。先读素材/定风格，再推导构图。

**本 skill 是分层结构**：这份 `SKILL.md` 只是索引 + 主流程，细节都在 `references/` 里。
**用到哪份读哪份，不要一次全读**——直接打开对应文件，例如 `references/02-排版思想.md`。

### 主流程（五步）

| 步 | 做什么 | 细节 |
|---|---|---|
| 1 | **列内容清单**：这张设计必须出现哪些信息 | `references/01-内容清单.md` |
| 2 | **读构图输入**：排版/字体/网格 + 主角 / 杠杆 | `references/02-排版思想.md` + `references/03-杠杆点.md` |
| 3 | **推导构图**：五个决定 → 区域 → 坐标 | `references/04-构图推导.md` |
| 4 | **构图之后**：运动感 / 外观对比 | `references/05-运动感.md` + `06-外观与对比.md` |
| 5 | **验收** | `references/07-自检与反模式.md` |

---

### §0 先问清（最多 3 个问题，别审问）

1. **投在哪 / 什么比例**——`1:1` 社媒方图 · `4:5` 海报/信息流 · `3:4` 印刷感 · `16:9` 网页头图 · `9:16` 竖屏故事。
2. **必须出现的文案**——标题、品牌、日期/价格、必须逐字保留的句子。
3. **有没有照片 / 参考图**——决定画面用「现成照片」「插画 / 图形」还是「不需要图」。

不要问「你想要什么风格」这种开放题；给 2–3 个方向让用户选（见 `06-外观与对比.md`）。

---

### §1 信息分层（在对话里写，不落盘）

按**信息关系**自然分组，不按“图位”拆。下面是常见关系，**只是提示，不是必须栏目**：

| 常见关系 | 回答的问题 | 可能是 |
|---|---|---|
| 钩子 | 为什么停下来看 | 主标题 / 一句狠话 / 一个数字 |
| 主体 | 这是什么 | 主体文字 / 照片 / 图形（不一定有图） |
| 支撑 | 凭什么信 | 细节 / 数据 / 一句解释 |
| 收口 | 下一步做什么 | 副标题 / 日期 / CTA / 落款 |

一张设计可以没有其中任何一层；**不要为了凑结构硬造信息**。

**一个版式只承担一个主动作**；第二个动作放副标题，第三个放注记。块数超过 5 就是没分层——先砍，再画。

---

### §2 内容清单（硬步骤）

把**这次要用的内容**摊开——用户给的原文、必须逐字保留的句子、你判断要补的词/数字/图像。
**不要先套“标题 / 副标 / 日期 / CTA”模板**：没有哪一类是必须的。

- 能标优先级就标（主角 / 次级 / 注记），不强制每条三档；
- 能选载体就选（文字 / 照片 / 插画 / 图形 / 数据图 / 留白）；
- 图的数量是**结果**，不是起点：0 / 1 / 2+ 都可能；
- 照片 / 插画是独立的画面内容；文字、图形、留白直接在版面上构成。

> 内容清单是**落版前的内部步骤**：把要用的内容摊开；何时向用户确认由 harness 的
> `ask_user` 决定，不在本 skill 里规定。
> 不需要凑栏目；哪怕只有一句话、只有一个词，也要先摊开。

清单的写法、载体、示例、反例，全部在：
**`references/01-内容清单.md`**

---

### §3 构图输入：排版与主角

推导之前先读两份，不要先画：

| 文件 | 管什么 | 先回答 |
|---|---|---|
| **`references/02-排版思想.md`** | 阅读路径 / 字体 / 网格 / 间距 / 字号层级 | 视线怎么走？字体/行宽/行距可读吗？ |
| **`references/03-杠杆点.md`** | 主角 / 六个杠杆 / 隔离与装框 | 主角是谁？用哪一两个杠杆？ |

读完写两句：

1. **主角是 X，因为 Y。**
2. **视线从 A → B → C；张力放在 Z。**

> 这两份不是“草图之后的评价标准”，是推导的输入。草图之后可以复读，但不要等到画完才第一次读。

---

### §4 构图推导（5 个决定）

**不要先选模板，也不要先数图。** 先回答五个问题：

| 决定 | 选项 | 回答什么 |
|---|---|---|
| **主角** | 文字 / 图像 / 图形 / 数字 | 第一眼必须看到谁？ |
| **图文关系** | 分离 / 并置 / 叠压 / 嵌入 | 文字和图像怎么相处？ |
| **骨架** | 满幅 / 分栏 / 网格 / 自由 | 版面靠什么组织？ |
| **阅读路径** | 上→下 / 左→右 / 中心向外 / 对角线 | 视线按什么顺序走？ |
| **张力** | 守格 / 破格 / 出血 / 重叠 / 大小对比 | 哪一处故意不一样？ |

把五个答案写成一句话，例如：

> 主角是产品；图文并置；2:3 分栏；视线从标题走到右下产品；张力在标题压出左边界。

**图的数量是结果**：先定内容和关系，最后核对 0 / 1 / 2+ 是否成立。
**结构没有名字**：同一组答案可以长出不同版式；不要套固定模板，也不要按编号轮换。
**同套图要错开**：按阅读路径 / 主角类型错开，不按“第几号结构”轮换。

推导、区域、图文关系、换比例与验收都在：
**`references/04-构图推导.md`**

> ⚠️ **满幅图先看素材的安静区**：文字放在画面的暗部 / 天空 / 桌面，不要默认放顶部；
> 主体在中间时把文字放到下方安静区，别用顶部 scrim 把主体压掉。

### §5 构图之后：动势与外观

| 要解决的问题 | 读哪份 |
|---|---|
| 画面太静、像说明书 | **`references/05-运动感.md`** |
| 配色 / 字体 / 对比 / 压暗 / 白底 | **`references/06-外观与对比.md`** |
| 提交前自检 | **`references/07-自检与反模式.md`** |

四条要点（全文见各文件）：

1. **一个画面只有一个主角**——用缩放 / 对比 / 定位 / 隔离里的**一两个**，不要全用。
2. **层级 ≠ 尺寸**——尺寸只是六个杠杆之一；隔离与装框同样能提升层级。
3. **运动感是设计意图**——递进 / 缩放对比 / 方向性 / 重复；方向性优先用不依赖旋转的斜向排列与阶梯缩进（见 05）。
4. **文字不是只能白字**——标题压图时，描边 / 阴影 / 渐变填充 / 超大字号该上就上；
   每个层级最多加 1–2 种，正文不加。

#### 三个检查点（硬性，不许跳过）

1. **推导之前**：读 `02-排版思想.md` + `03-杠杆点.md`，写「主角是 X，因为 Y」和视线路径；写不出来就还没设计。
2. **写坐标之前**：读 `04-构图推导.md`，把五个答案写成一句构图意图；写不出来不落版。
3. **调外观之前**：读 `06-外观与对比.md`，检查四角色、强调色是否只给主角、文字压图有没有 scrim；再回 `02` 查间距档差。

> 这三步是**必须读**，不是"按需"。漏掉第 1 步会出现"构图意图对了但画面平"，漏掉第 2 步会出现"标题和副标隔了很远还说是紧贴"，漏掉第 3 步会出现"配色每行一个颜色"。

---

### §6 执行顺序

> 用户还没定风格时，先按 `design-style` 给 2–3 个方向、写一份 style brief；
> 风格已定就直接从内容清单开始。

1. 内容清单 → **先列内容清单**（内部步骤；是否向用户确认由 harness 决定）。
2. 构图输入：读 `02` + `03`，写「主角是 X」和「视线 A → B → C」。
3. 构图推导：读 `04`，五个问题写成一句意图；定区域与骨架，再回 `02` 查间距、`03` 查主角。
4. 进入版式阶段：把区域、比例、字号档落成草图；有构图问题就改区域 / 骨架，不要用外观掩盖。
5. 标记需要照片 / 插画的内容项（其余由文字 / 图形 / 留白承担）；这些内容项只描述要什么画面。
6. 外观：按 `06` 处理颜色 / 字体 / **文字效果**（描边、阴影、渐变填充、富文本）；位置 / 尺寸 / 变换按当前阶段能力处理。
7. 请用户看草图；告诉他主角是谁、图文是什么关系、几张图、下一步可调什么。

> 版面关系真的变了（加 / 删 / 复制元素）属于版式阶段，不在外观阶段硬改；
> 已有版式的小改动优先在原版式上调整，不要为了改一处重新开一版。

---

### §7 三条铁律

1. **先内容清单，再构图输入，再推导，最后外观**——顺序反了就会退化成"一张图 + 文字堆"。
2. **一次只用一个杠杆点手段的一两个**——堆砌会变成视觉噪音。
3. **说不清它为什么存在的元素，删掉**——每个元素要么增加清晰度，要么就是噪音。
