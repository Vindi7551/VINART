能力账本 04 · 边界：DOM 做不到 / 需额外引擎的

这一页全是负例——展示 DOM 给出的版本，以及为什么不够。
变宽笔触（沿路径粗细变化）❌ 原生不行
SVG stroke-width 沿线恒定。要"由粗到细"须先算出变宽轮廓（几何计算）再填充
液化 Liquify❌ 需光栅
上面是未液化的原图。液化 = 可交互控制的网格变形；feDisplacementMap 只能做固定位移，做不到"用笔刷推"
操控变形 Puppet Warp❌ 需光栅
需"加钉子 + 骨架形变"；浏览器无对应能力，须自建网格解算（CPU/GPU）
内容识别填充❌ 需算法/模型
需 inpainting 算法（WASM）或 生成式模型（外部 API）——DOM 无任何对应
真实笔刷（压感 / 纹理累积）❌ 需光栅
DOM 只能画均匀几何笔画；压感宽度、笔尖纹理、笔画间的混合累积都要光栅画笔引擎
布尔路径运算⚙️ 需几何引擎
并/交/差/排除要找几何库先算（如 paper.js / clipper），算出新路径再交给 SVG 渲染——不是 DOM 的活
