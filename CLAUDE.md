## Project Overview

Vinart is an AI-powered design-to-image agent, implemented in **TypeScript**. Unlike traditional design agents that manipulate graphics directly, Vinart treats layout and element composition as **HTML+CSS code**, leveraging the Blink browser engine's sub-second rendering to produce design images.

## Core Pipeline

```
Input (reference image + text description + use case)
  → designAgent (design concept)
    → translateAgent (style/layout heuristics)
      → codeAgent (HTML+CSS layout framework)
        → vision model (per-element image generation, fills layout slots)
          → Render layer (Blink → composite image)
```

- **codeAgent** generates the HTML+CSS layout skeleton — structure, positioning, typography, spacing.
- **Vision models** generate individual image assets (product shots, backgrounds, decorative elements) that populate slots within the layout. These are prone to hallucination and may need individual regeneration.
- The final composite is rendered through Blink as a single image.

## Architecture

- **`src/agent/`** — Agent role definitions. Each agent has its own prompt and capabilities. Each agent's `prompt.ts` defines its `systemPrompt` and handles dynamic assembly of additional prompts (exact assembly mechanism is still being designed):
  - `designAgent/` — Analyzes reference images, text descriptions (e.g., selling points), and usage scenarios to produce a design concept.
  - `translateAgent/` — Translation layer. Converts the abstract design concept into concrete style requirements and layout heuristics for code generation.
  - `codeAgent/` — Generates HTML+CSS code from the translateAgent's output.
- **`src/gateway/`** — External request gateway. Protocol adapters (OpenAI, Volcano Ark), HTTP client with retry/timeout, fallback chain.
- **`src/session/`** — Chat session management. Maintains message history, calls gateway for streaming responses.
- **`src/config.ts`** — API key configuration. Reads from environment variables and provides pre-built gateway instances.
- **`src/render/`** — Rendering layer. Takes codeAgent output and renders it through the Blink engine into previewable images for the frontend.
- **`src/template/`** — Template library. Stores curated, proven design templates (both descriptions and reference code) that agents can draw from.
- **`src/ui/`** — Frontend. Expected to include a chat/dialog interface, a material upload area, and a render preview panel.

## Key Design Decisions

- **HTML+CSS as the intermediate representation** for layouts — this is what differentiates Vinart from traditional pixel/raster-based design agents. All design elements (typography, spacing, composition) are expressed as web code.
- **Blink engine** is used for rendering because of its production-grade, sub-second rendering speed — far faster than headless design tools.
- The **translateAgent** serves as a critical bridge: design language (e.g., "minimalist luxury feel") must be decomposed into actionable CSS heuristics (e.g., "ample whitespace, serif font, muted gold accent") before code generation can happen.
- **Per-element image generation**: Visual elements within a layout (product images, backgrounds, etc.) are generated by vision models based on reference descriptions. These models hallucinate, so individual elements must be selectable for targeted regeneration without redoing the entire design.

## UI Layout Plan

Left-right split layout (desktop). The left is the preview area, the right is the conversation/interaction area.

- **Header**: Project name, [New Conversation] button.
- **Left (Preview)**:
  - Render result preview (full composite).
  - Below the preview: a list of selectable image elements extracted from the rendered design. Users can check individual elements and trigger targeted regeneration (addresses vision model hallucination).
- **Right (Conversation)**:
  - Chat message stream (multi-turn interaction for iterative refinement — "make the title larger", "warmer colors").
  - Material/asset thumbnails appear inline within chat bubbles (similar to how LLM web apps show uploaded images).
  - Input area at the bottom with [Upload] and [Send] buttons.
- **Debug overlay** (dev only): Pipeline step visibility (design → translate → code → render) shown in the conversation area to aid debugging. Hidden in production.
