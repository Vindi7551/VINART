## 0. 一句话结论

**差距不在"版式排版"，而在"图像生产的物理层"。**

vinart 的 8 张图**结构全部正确、文案全部正确、排版全部可读**——它们是一套**合格的"信息图"**。
模范本是**"实拍质感的商品广告图"**。

两者的分野是一句话：**vinart 在"白底商品照上叠文字框"；模范本在"真实场景中重拍产品"。**

| 量化指标（均值） | 模范本 | vinart | 差距 |
|---|---|---|---|
| **白底占比** | **9.2%** | **65.5%** | 7.1× |
| **平均饱和度** | **0.472** | **0.109** | 4.3× |
| 平均亮度 | 0.571 | 0.901 | 过曝 +58% |

（口径：8-bit PNG 全图抽样，每 ~400px 一点；白底=RGB 全 >245）

## 1. 逐张对比（G↔PT）

> PT02 与 G02 都讲"适配性"、PT06 与 G06 都讲"两种场景"、PT08 与 G08 都讲"送礼"——同题对比最能看出差距来源。

### 1.1 同题对比 A：PT02「适配」vs G02「全套包含」

| | 模范本 G02 | vinart PT02 |
|---|---|---|
| **产品呈现** | 主图 = **真实场景**中的产品（干草/南瓜/秋叶/木栅栏） | 主图 = **纯白底实拍图**，四周大片留白 |
| **细节呈现** | 右侧 **3 个圆形放大特写框**，每个都指向产品具体部位（鹅头/翅膀/帽子），有**引线指向** | 右侧 **3 个纯文字标签牌**，**无特写、无指向** |
| **信息密度** | 一屏同时给出"整体+3 处细节" | 一屏只给"整体 + 3 个名词" |
| **边框装饰** | 四角枫叶角饰 + 双层描边框 | 无 |

**关键差异**：模范本用**"特写框"证明卖点**；vinart 用**"标签牌"声称卖点**。前者是"我指给你看"，后者是"我说给你听"。

### 1.2 同题对比 B：PT06「两场景」vs G06「两场景」★最重要

两者**结构几乎一样**（两图并排 + 底部标签 + 一行注记），但观感差距最大：

| | 模范本 G06 | vinart PT06 |
|---|---|---|
| **产品与场景关系** | **产品真实站在场景里**——室内玄关、门廊，有透视、有接触阴影、有环境光 | 产品**贴在场景图上**——左右两图都是同角度产品照，背景是**生成出来的空场景** |
| **场景内容** | 真实家居环境（木地板/门/装饰/植物） | 生成场景（门廊/庭院），**单独看是"空场景"** |
| **白底占比** | ~0.2% | 55.4% |
| **饱和度** | 0.384 | 0.259 |

**铁证**：`PT06/assets.json` 的生图提示词里**明确写了** `Keep the bottom-left area of the frame clean and uncluttered`——**主动为后期贴图留位**。说明链路**架构上就是"背景图 + 前景图层叠加"**，从未打算做"产品真融入场景"。

> ⚠️ 这与 `workflow/assetsgen/order.ts` 的既有规定直接相关：**"背景类节点禁止出现产品、人物、文字——前景内容由版式层叠在上面"**。也就是说：**PT06 的"贴图感"是设计使然，不是失误。**

### 1.3 全套共性差异（8 张全部成立）

| # | 差异 | 模范本 | vinart | 影响 |
|---|---|---|---|---|

| 2 | **背景** | 场景/图案/双色底，有景深 | 94% 纯白 | 廉价感 |

## 2. 根因分析：为什么会差这么多？（三层）

### 2.1 【架构层】渲染器只能"叠"，不能"融"

`render.ts` 的 image 节点 = `<img style="object-fit:...">` 放进容器。**纯叠加**，结构上不可能做阴影融合、透视匹配、环境光匹配。

→ 所以只要"产品与场景不是同一张图"，就必然有"贴图感"。**这是硬约束。**

### 2.2 【规范层】`order.ts` 的"背景类禁止含产品"把路堵死

- `order.ts` 规定 `bg-*` 纯装饰底纹、`scene-*` 曾归入"背景类"；
- 背景类**禁止出现产品**，要求"前景由版式层叠"。
- **结果**：订单生成模型只会产"空场景"，产品永远靠贴。

> 注：`order.ts` 在 2026-10-11 已加入「**产品在场景中**」新类（要求用 `@product` 直出整图）。**但本次 8 张图全部早于该修改**，所以仍是旧行为。**这是最有价值的待验证项。**

### 2.3 【流程层】brief 写了"氛围"，但没写"必须重拍"

PT01 的 `brief.md` 里氛围要求写得很细：

> 「温暖、丰收、秋日门廊、幽默可爱但不幼稚；干净留白，移动端缩到小图也能一眼读清标题。」

**但**：
- 没有一句要求"产品必须在真实场景中"；
- 反而写了「**整体干净留白**」——**与模范本的"满构图、无留白"直接冲突**；
- 子 agent 的 tools 里**只有** `save_spec`/`validate_sketch`/`render_sketch`/`read_file`——**没有任何生图能力**（生图在主线，且要确认）。

→ **子 agent 只能摆框，图像质量由主线决定。**而主线把"生图"放在最后一步（第 6 步），此时版式已定死为"白底 + 标签牌"。

## 3. 对话文件分析：4 个流程级优化点

### 优化点 1 🔴 **spawn 参数 JSON 截断（真 bug，导致重试）**

事实：`spawn_design_agents` 有一次失败：

```
ERROR: 工具调用失败：Unterminated string in JSON at position 2015 (line 1 column 2016)
```

**根因**：brief 全文写进 `jobs[].brief` 参数，模型输出被 `max_tokens` 截断 → JSON 不合法。

**已存在的护栏**：工具限制"单次 ≤3 job"，第二次失败正是这条护栏在起作用（派了 5 个被拒）。**但护栏挡不住"单个 brief 太长"**。

**建议**（不改，仅列）：
- brief 改为**落盘文件 + 传路径**，而不是塞进参数（既省 token 又免疫截断）；
- 或在工具侧把"brief 长度上限"也做成显式断言。

### 优化点 2 🟠 **`compile_appearance` 被调用 8 次（串行）**

事实：8 次独立调用，耗时 6.7–15.7s，**合计约 80s**。

**问题**：8 张图属于**同一套**，配色**应共享同一 palette**。逐个编译 = 8 倍成本 + 存在"同套不同色"的漂移风险。

**建议**：编译一次 → 8 张复用；或提供批量参数 `{names:[...]}`。

### 优化点 3 🟠 **主线把"生图"放在最后，导致版式已定型**

事实：时间线是 `spawn×5 → compile×8 → render×7 → generate_assets×1 → render×1`。

**问题**：版式（sketch）**先于**素材（assets）确定。等发现"想要场景图"时，版式已经是"白底 + 标签牌"的结构。

**建议**：在**派子 agent 之前**先决定"本套图的图像策略"（白底 or 场景），并让 brief 与订单都服从它。

### 优化点 4 🟡 **只有 1 张（PT06）用了生成素材，其余 7 张直接贴用户原图**

事实：8 张里 7 张的 `product` 节点 `asset = uploads/chat-...jpg`（用户原图，未抠图）。

**问题**：① 白底原图直接当主图 → 大面积留白；② 未抠图 → 无法与背景融合；③ 同一张原图在 8 张里重复出现 7 次 → **同套图内视觉重复**。

**建议**：至少做**抠图 + 一次重拍**，让每张各不相同。

## 4. 建议的"合理范式"（对齐模范本）

### 4.1 图像策略范式（最重要）

> **一套图的图像策略，必须在派子 agent 之前定死，且分三档。**

| 档位 | 做法 | 适用槽位 | 成本 |
|---|---|---|---|
| **A · 场景重拍** | `@product` 直出"产品在场景中"整图 | 场景类（PT04/06/07/08） | 每张 1 次生图 |
| **B · 白底主图** | 抠图后纯白底（**仅 1–2 张保留**） | 识别类（PT01） | 1 次抠图 |
| **C · 特写裁切** | 从场景图裁切局部，配引线指向 | 细节类（PT02/03/05） | 0 次生图（复用） |

**关键原则**：**白底图在一套里占比必须 ≤25%**（模范本实测 9.2%）。超过就是"信息图"而不是"广告图"。

### 4.2 版式范式（对齐模范本）

| 要素 | 模范本做法 | 建议落进 brief/spec |
|---|---|---|
| 背景 | 场景图 / 图案 / 双色，**无纯白** | 禁止 `#FFFFFF` 满底 |
| 标题 | 大号 + 描边/阴影 + 双色强调 | 标题加 `text-shadow` 或描边 |
| 细节证明 | 特写框 + 引线指向**产品边缘** | 标签牌必须配引线，且指向具体部位 |
| 装饰 | 四角角饰 + 描边框 | 每条边加装饰层（可复用元素） |
| 衬底 | 米白/奶油 | 中性色用暖白 `#FDFBF7` 而非纯白 |
| 文字层级 | 标题 → 标签 → 注记（三级） | 已在做，保持 |

### 4.3 证据链范式

模范本的每张图都**在证明一个可验证的卖点**（"全包含"给特写、"保暖"给内部结构）。vinart 目前多为"声称"。

**建议**：brief 里强制一问——**"这张图用什么视觉证据证明它的主张？"** 若答案是"文字标签"，则不合格。

## 5. 优先级排序（若日后要改）

| 优先级 | 项 | 层 | 预期收益 |
|---|---|---|---|
| **P0** | 图像策略三档（4.1） | 流程+规范 | 直接解决 80% 观感差距 |
| **P0** | brief 禁止"干净留白"、要求"满构图" | 规范 | 消除与模范本的直接冲突 |
| **P1** | 细节图强制"特写框+引线" | 版式+规范 | 补齐"卖点可证" |
| **P1** | 装饰系统（角饰/描边） | 渲染层 | 提升"完成度" |
| **P2** | `compile_appearance` 批量复用 | 工具 | 省 ~70s + 防色漂 |
| **P2** | brief 落盘传路径 | 工具 | 免疫 JSON 截断 |
| **P3** | 抠图后再贴（替代原图直贴） | 流程 | 去白边、可融合 |

## 6. 未验证项（诚实标注）

1. **`order.ts` 的「产品在场景中」新规定是否有效**——本次 8 张图**全部早于**该修改，**未经实测**。这是 P0 的核心，建议优先验证。
2. **模范本是否 AI 生成**——G01（纯白底）与其余 7 张风格不连续，G01 可能是原图，其余为成品设计。**不影响结论**（对标的是"成品应有的样子"）。
3. **渲染器能否支持"融合"**——本文档认定"结构上只能叠加"，**未做实验证明**；若要"真融合"，可能需改渲染层（重）。
